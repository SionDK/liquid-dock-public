## 원본과 다른 점

원본의 기능(리퀴드 글라스, 자동 숨김, 확대 효과, 알림 튐, 원클릭 버튼, Windows 트레이 창 열기, 작업표시줄 고정 앱 가져오기 등)은 그대로 두고,
아래를 더하거나 바꿨습니다. 자세한 것은 각 절에 있습니다.

**더한 것**

- **HWiNFO에서 온도 받기** – 드라이버나 관리자 권한 없이 HWiNFO의 Gadget 값으로 CPU 온도, 메모리 모듈 온도, VRAM 온도를 받습니다(기본값).
  설정에 **센서** 페이지가 생겨 온도를 어디서 읽을지(끄기 / HWiNFO Gadget / PawnIO)와 'PC 상태' 패널·칸에 보일 항목을 고릅니다.
- **'PC 상태' 패널을 새로 만듦** – CPU·GPU 카드, RAM, 메모리 모듈마다의 슬롯과 온도, VRAM, 드라이브마다의 온도를 보입니다.
- **배터리 칸** – 노트북에서 잔량, 충전 상태, 남은 시간을 보입니다.
- **시작 버튼이 기본 작업 표시줄의 시작 단추처럼** – 숨겨 둔 작업 표시줄의 시작 단추를 UI 자동화로 누르고, 안 되면 셸 요청과 Win 키로
  넘어갑니다. 관리자 권한 창이 앞에 있거나 재부팅 직후 시작 메뉴가 늦게 떠도 열립니다.
- **앱 아이콘 클릭을 작업 표시줄 규칙대로** – 최소화된 창, 시작·검색이 열린 상태, 관리자 권한 창이 앞에 있는 상태 등에서 클릭이 헛돌지 않게 했습니다.
- **창 미리보기에서 창 닫기** – 카드의 닫기(X) 단추나 휠 클릭으로 닫고, 최소화된 창은 최소화되기 직전 모습이 나옵니다.
- **트레이 아이콘 표시(실험)** – 작업표시줄에 꺼내 둔 트레이 아이콘을 독에 두 줄로 보입니다.
- **FluentFlyout 연동** – FluentFlyout의 작업 표시줄 위젯을 독 안에 넣고 Flyout을 독 위에 맞춥니다.
- **관리자 도우미의 창 제어** – 관리자 권한으로 실행한 앱의 창을 복원·최소화·닫기하고, 그런 창 앞으로 다른 창을 가져옵니다. 설치 프로그램이 설치된 도우미도 바꿉니다.
- **기다리는 동안 가볍게** – 볼륨·네트워크·마우스·센서를 확인하는 간격을 줄이거나 알림으로 바꿔, 독이 쉬는 동안 깨어나는 횟수를 줄였습니다.
- **일반 권한으로 다시 시작** – 독이 관리자 권한으로 시작되면 일반 권한으로 다시 시작합니다(`--keep-admin`이면 그대로).
- **테스트** – 단위·통합 테스트(`tests\run_regressions.bat`)와 실제 Windows에서 돌리는 실기기 테스트, 로컬 LLM 작업 모음(`tools/llm-tasks/`).

**바꾼 것**

- 시스템 모니터 칸을 클릭하면 작업 관리자가 열립니다. 원본처럼 칸을 클릭해 PawnIO를 켜지 않고, 설정 → 센서나 칸의 우클릭 메뉴에서 고릅니다.
- 원본 패널의 1분 사용률 그래프와 SSD 활동·용량 표시는 없앴습니다.
- 최소화된 창의 미리보기는 "최소화된 창 · 클릭하여 복원" 문구 대신 최소화되기 직전 모습입니다(Windows가 아무 모습도 주지 않을 때만 문구).

## 특징

- **진짜 리퀴드 글라스** – 독 뒤 화면을 실시간으로 받아 GPU 셰이더로 굴절·색수차·흐림·하이라이트를 입힙니다. 배경이 밝으면 글자색도 자동으로 바뀝니다.
- **마우스를 올릴 때만 등장** – 화면 가장자리에 마우스를 대면 스프링 애니메이션으로 나타나고, 벗어나면 숨습니다.
  - 숨어 있는 독은 Win+Shift+S(캡처 도구)의 창 캡처 모드에서 창으로 골라지지 않습니다. 예전에는 독이 쓸 수 있는 띠 전체(독
    위쪽 빈 곳까지)가 창으로 골라져, 그 밑 창의 아랫부분만 찍혔습니다. 단, FluentFlyout 위젯이 들어간 독이 숨은
    동안에는 위젯 칸 크기의 사각형이 아직 골라질 수 있습니다(고치지 않은 알려진 버그, 아래 [알려진 한계](#알려진-한계)).
- **맥 같은 확대 효과** – 아이콘 위에서 물결처럼 커집니다. 아이콘 줄을 옆으로 벗어나 트레이·시계나 FluentFlyout 위젯 위로 가면 아이콘은 원래 크기로 돌아가고, 포인터가 있는 쪽 끝은 제자리에 둔 채 반대쪽 끝만 줄어듭니다.
- **알림은 통통 튀게** – 카톡 등 앱이 알림을 보내면 독은 숨긴 채 해당 아이콘만 화면 끝에서 고개를 내밀고 튑니다(메인 모니터).
- **상하좌우 어디든** – 모니터마다 독이 하나씩 뜹니다. 크기는 Windows 배율이 아니라 화면 크기에 맞춰져서, 해상도가 다른 모니터에서도 화면에서 차지하는 비율이 같습니다.
- **시스템 모니터** – 독 맨 끝 칸에 CPU/GPU 온도(온도를 모르면 사용률)가 나옵니다. 칸은 패널이 닫혀 있으면 2초마다 갱신됩니다(예전 1초).
  과열(CPU 90°C, GPU 83°C, 시스템 드라이브 70°C 이상)이면 한 번만 튀어서 알려 줍니다. 칸에 마우스를 올리면 'PC 상태' 패널이 열립니다.
  - 온도를 어디서 읽을지(끄기 / HWiNFO Gadget / PawnIO)와 패널·칸에 무엇을 보일지는 설정 → **센서**에서 고릅니다(아래 [설정](#설정)).
    숨긴 항목은 패널과 칸에서 빠지고 과열 알림도 울리지 않습니다. GPU를 숨기면 칸에는 CPU 한 줄만 가운데에, CPU 온도를 숨기면 CPU 사용률이 나옵니다.
  - 칸은 보이는 숫자(정수)나 색이 바뀔 때만 다시 그립니다. 예전에는 값이 같아도 2초마다 다시 그려, 늘 떠 있는 독이 쉬는 동안에도 시간당 1,800번
    창 전체를 다시 그렸습니다. 잠겨 있거나 화면이 꺼져 있는 동안에는 센서 때문에 다시 그리지 않고, 돌아오면 한 번 그립니다. 칸이 온도 대신 사용률을
    보이면 거의 매번 바뀌므로 이득이 적습니다. 열려 있는 패널은 그대로 1초마다 다시 그립니다.
  - 패널은 위에서부터 이렇게 생겼습니다(설정에서 숨긴 줄은 빠짐).
    - 머리글 "PC 상태"와 오른쪽의 "CPU · GPU · RAM · SSD"(GPU에 전용 메모리가 있으면 "CPU · GPU · RAM · VRAM · SSD", 숨긴 GPU·VRAM·SSD는 빠짐)
    - CPU·GPU 카드 두 장: 큰 온도, 모델명, "사용률 N%"와 사용률 막대
    - RAM: 사용량(예: `14.2 GB / 62.8 GB`), 사용률(%), 막대
    - 메모리 모듈마다 슬롯과 온도(예: `RAM 1 · A2  35.8°C`, 소수 한 자리)
    - VRAM(GPU의 전용 메모리): RAM과 같은 꼴로 사용량(예: `1.9 GB / 8.0 GB`), 사용률(%), 막대(GPU 카드와 같은 초록)와 그 아래 줄에
      `VRAM 온도  44.0°C`(소수 한 자리). 전용 메모리가 있는 GPU일 때만 나오고, 전용 메모리가 없거나 작은(1 GB 미만) 내장 그래픽이면 이 줄들과 머리글의 "VRAM"이 없습니다.
    - 문자가 붙은 내장 드라이브마다 문자, 모델명, 온도(예: `D:  WD SN850X  42°C`)
    - 바닥글 "SSD 3/3 · RAM 2/2 · 1초 갱신": 온도를 읽은 드라이브 수 / 드라이브 수, 온도를 읽은 모듈 수 / 꽂힌 모듈 수
  - 패널이 열려 있는 동안은 1초마다 갱신되고, 열자마자 한 번 새로 읽습니다(첫 읽기 전에는 "측정 중…").
  - 드라이브 목록과 온도, 메모리 온도는 패널이 열려 있는 동안(닫은 뒤 5초까지)만 읽습니다. 드라이브 온도를 매초 물으면 NVMe가
    저전력 상태로 못 들어가기 때문입니다. 패널이 닫혀 있을 때는 칸과 과열 알림에 필요한 것(CPU·GPU 온도와 사용률, RAM)만 2초마다,
    시스템 드라이브 온도는 5초마다 읽습니다.
  - 색은 예전 패널 그대로입니다: 어두운 유리 위에 흰 글자, 사용률 막대는 CPU 파랑·GPU 초록·RAM 보라.
  - 온도 색: 평소에는 흰색, 경고 온도의 10°C 아래부터 주황, 경고 온도부터 빨강입니다. 드라이브는 70°C, 메모리는 85°C가 경고 온도입니다(CPU·GPU는
    위와 같음). 모르는 값은 흐린 `--°C`입니다.
  - VRAM 사용량은 NVIDIA면 드라이버(NVML)에서, 그 밖의 GPU는 HWiNFO에서 받아 옵니다. VRAM 온도는 드라이버가 주지 않는 카드가 있어
    그런 카드는 HWiNFO에서 받아 옵니다. 아래 [CPU 온도](#cpu-온도-선택-기능)의 4번처럼 HWiNFO에서 **GPU 메모리 접합 온도**(영어 `GPU Memory
    Junction Temperature`)를 체크해야 나오고, 체크하지 않았거나 그 카드에 그런 센서가 없으면 `--°C`와 흐린 "HWiNFO Gadget 필요"가 나옵니다(가로 독은
    오른쪽 열, 세로 독은 이름 옆). VRAM 온도는 100°C부터 빨강, 90°C부터 주황입니다. 과열 알림에는 넣지 않았고, 패널이 열려 있는 동안만 읽습니다.
    '온도 읽기'가 끄기나 PawnIO이면 HWiNFO를 읽지 않으므로, VRAM 온도 줄은 드라이버가 그 온도를 주는 카드에서만 나옵니다("HWiNFO Gadget 필요" 힌트도 HWiNFO Gadget일 때만).
  - 메모리 온도는 HWiNFO에서 받아 옵니다. 아래 [CPU 온도](#cpu-온도-선택-기능)의 3번처럼 모듈마다 체크해야 나오고, 체크하지 않았으면
    슬롯 이름 옆에 `--°C`로 나옵니다. 노트북처럼 메모리가 기판에 붙어 있으면 메모리 줄과 바닥글의 RAM 부분이 없습니다.
    '온도 읽기'가 HWiNFO Gadget일 때만 나옵니다(끄기·PawnIO에서는 메모리 줄이 빠짐).
  - USB 드라이브, SD 카드, VHD는 목록에 넣지 않습니다. 한 디스크에 문자가 여럿이면 가장 앞 문자 하나만 나옵니다.
  - VRAM 줄이 더해지면 가로 독의 창 두께가 71 DIP(100%에서 71 픽셀) 늘어납니다. 독을 켤 때 GPU의 전용 메모리가 1 GB 이상이거나 NVIDIA 그래픽 카드가
    있으면 그 자리를 미리 잡고, 그렇지 않은 PC(노트북의 내장 그래픽 등)는 창 크기가 그대로입니다. NVIDIA 카드는 '온도 읽기'가 끄기·PawnIO여도 VRAM 온도 줄의
    자리(27 DIP)를 잡아 둡니다(드라이버가 그 온도를 주는지는 패널을 처음 열 때에야 알 수 있어서). 설정에서 숨긴 줄은 자리를 잡지 않으므로, 가로 독은 숨긴
    만큼 창이 얇아집니다(세로 독은 그대로).
  - 독을 켤 때보다 드라이브나 메모리 줄이 늘어 패널에 다 들어가지 않으면 드라이브부터 들어가는 만큼 보입니다. 나머지는 바닥글
    오른쪽에 "SSD 외 N개", "RAM 외 N개"로 셉니다(독을 다시 켜면 자리가 늘어남).
  - 독을 왼쪽·오른쪽에 두면 패널이 좁아지고(320, 가로 독은 450) 메모리·드라이브를 한 줄에 하나씩 놓습니다. 세로 독에서는 패널 폭이
    독 창의 두께가 되어, 가로 독과 같은 폭이면 창이 3분의 1쯤 커지기 때문입니다.
  - CPU 온도가 없으면 CPU 카드에 까닭이 나옵니다. '온도 읽기'가 HWiNFO Gadget이면 "HWiNFO 설정: 클릭"(HWiNFO가 켜져 있음) 또는 "HWiNFO Gadget 필요",
    PawnIO면 도우미가 알려 준 까닭 또는 "온도: 도우미 시작 중…"이고, 끄기이거나 CPU 온도를 숨겼으면 아무것도 나오지 않습니다. 사용률 옆에 다 들어가지 않으면
    모델명 자리에 나옵니다. NVIDIA가 아닌 GPU는 온도 대신 "온도: NVIDIA만 지원"이 나옵니다.
  - 칸이나 패널을 클릭하면 작업 관리자가 열립니다. '온도 읽기'가 HWiNFO Gadget이고 HWiNFO는 켜져 있는데 CPU 온도가 없을 때만 HWiNFO 설정 안내가 뜹니다.
    예전처럼 칸을 클릭해 PawnIO를 켜지는 않습니다.
  - 긴 모델명은 끝이 "…"로 잘립니다.
  - 예전 패널의 1분 사용률 그래프와 SSD 활동·용량 표시는 없앴습니다.
  - GPU 드라이버 업데이트나 그래픽 재설정(TDR) 뒤에도 센서·배터리·시계 칸의 폭이 맞습니다. 예전에는 배율이 다른 화면을 썼던
    실행(외부 모니터를 꽂은 노트북, 해상도 변경)에서 칸이 좁거나 넓어져 글자가 옆 칸에 겹칠 수 있었습니다.
- **배터리** – 노트북에서는 시스템 모니터 칸과 버튼 사이에 배터리 칸이 생깁니다(데스크톱에는 없음).
  - 작은 버튼보다 큰 배터리 아이콘 아래에 잔량(%)이 나옵니다. 전원에 연결되면 초록색, 충전 중이면 번개 표시,

    더 보내거나 묻지 않고(셸 요청, Win 키, 작업 표시줄 단추 모두), 시작 메뉴를 띄울 모니터도 바꾸지 않습니다. 그래서 오던 시작 메뉴가
    두 번째 요청에 멈추거나, 닫은 시작 메뉴가 다시 뜨거나, 독이 둘인 PC에서 시작 메뉴가 다른 모니터로 옮겨 가지 않습니다.
  - 재부팅 직후 Explorer가 바빠 셸에 닿기까지 오래 걸려도, 기다리는 시간은 셸에 요청을 보낸 뒤부터 셉니다.
  - 어느 쪽이 통했는지 기억해서, 셸 요청이 두 번 연달아 시작 메뉴를 띄우지 못하면 다음부터는 Win 키를 먼저 쓰고(Win 키가
    안 통하면 셸에 다시 요청), 셸이 시작 메뉴를 띄우면 다시 셸을 먼저 씁니다. 셸에 아직 닿지 못한 클릭은 세지 않습니다.
  - 시작 메뉴가 0.6초 넘게 걸렸거나, 다른 방법으로 대신 떴거나, 끝내 뜨지 않으면(셸이 거절했으면 4초, 받았으면 8초 뒤)
    `data\dock.log`에 `start:` 줄로 작업 표시줄 단추를 눌렀는지(어떻게 눌렀고 어디서 찾았는지), 셸의 대답, Win 키를 눌렀는지(안 눌렀으면
    이유), 앞에 있던 프로그램과 관리자 권한 여부, 기다리는 동안 더 누른 횟수, 보낼 준비에 걸린 시간을 남깁니다. 평소처럼 바로 뜨면
    실행마다 첫 번째만 한 줄 남기고, 작업 표시줄 단추를 믿게 되거나 그만 쓰게 될 때도 한 줄씩 남깁니다.
  - 시작 메뉴는 키보드도 받아서, 열리자마자 검색어를 칠 수 있습니다(독이 창을 바꿀 권한을 받아 셸에 넘겨 줌).
  - 시작 메뉴가 열려 있을 때 누르면 닫힙니다(아직 기다리던 요청이 있으면 그것도 멈춰서 다시 열리지 않습니다). 열려 있는지는
    Windows의 IAppVisibility로 봅니다. Windows 11 25H2에서는 시작 메뉴가 열려 있어도 앞 창이 검색 상자(SearchHost)라서,
    앞 창만 보던 mod.15는 열린 시작 메뉴를 놓칠 수 있었습니다.
- **Shift+클릭** 으로 앱을 관리자 권한으로 실행합니다.
- **앱 아이콘 클릭은 Windows 작업표시줄 규칙 그대로** – 앞에 떠 있는 창이면 최소화하고, 그 밖에는 창을 다시 띄웁니다.
  - 창이 하나뿐인 앱은 숨겨 둔 Windows 작업 표시줄에서 그 앱의 단추를 대신 눌러(UI 자동화), Windows가 작업 표시줄을 클릭했을
    때와 똑같이 창을 띄우거나 내립니다. 단, 앱 단추가 UI 자동화로 누를 방법(Invoke, Toggle)을 주는 Windows에서만입니다.
    **확인한 Windows 11 25H2 빌드의 앱 단추는 접근성 기본 동작('누르기')만 주는데, 이 동작은 성공이라고 답하고도 아무 일도
    하지 않습니다**(작업 표시줄을 숨겼을 때도 보일 때도, 2026-10-27 실기기 확인). 확인한 Windows 11 26H2 빌드의 앱 단추도 그 기본
    동작만 줍니다(2026-10-28 실기기 확인). 이런 Windows에서는 단추를 누르지 않습니다.
    그 실행에서 앱 단추를 처음 찾았을 때(탐색기가 느려 1초를 넘기거나 단추를 못 찾은 클릭이면 그다음 기회에) 이를 알아보고 바로
    독이 직접 처리하며, 그 실행 동안은 아래의 독 규칙만 씁니다(mod.21은 헛누름 뒤 1.6초를 기다렸다가 독이 처리했음). 고정된 앱이 실행 중이 아니면 그 앱의 고정 단추로 실행합니다(그 실행에서 작업 표시줄 단추가
    제대로 동작하는 것을 한 번 본 뒤부터). 창이 여럿인 앱은 아래의 독 규칙과 독의 미리보기를 그대로 씁니다. 작업 표시줄 단추로
    누르면 숨은 작업 표시줄 자리에 Windows의 미리보기가 뜨기 때문입니다. 최소화됐는데 아직 활성 창으로 남은 창, 화면 밖에 있는
    창처럼 독이 따로 고쳐 둔 경우와, 그 앱의 대화 상자처럼 작업 표시줄 단추가 없는 그 앱의 창이 앞에 있을 때(작업 표시줄은 앱이
    이미 앞에 있다고 보고 창을 내릴 수 있어서)도 독이 처리합니다.
    - 그 앱의 단추 가운데 독이 센 창 수와 맞는 단추만 누릅니다. 실행 중인 창 하나면 창 1개를 세는 단추, 실행이면 창을 세지 않는
      고정 단추입니다(모니터마다 작업 표시줄이 있으면 모두 찾아봄). 그런 단추가 없거나 누르기가 실패하면 독이 바로 직접
      처리하고, 단추를 못 찾은 앱은 60초 동안 다시 찾지 않습니다.
    - 단추를 찾고 누르는 일은 따로 도는 스레드가 해서, 탐색기가 바빠도 독은 멈추지 않습니다. 탐색기가 1초 안에 단추를 찾아
      누르지 못하면 독이 직접 처리하고(그 뒤에 단추가 눌리는 일은 없음), 30초 동안은 모든 앱을 독의 방식으로 처리합니다.
      누르는 도중에 탐색기가 응답하지 않아 전달됐는지 알 수 없으면, 독은 그 창에 아무것도 하지 않고(같은 앱을 다시 누르거나
      미리보기에서 그 창을 골라도) 최대 8초까지 지켜봅니다. 고정 앱 실행이었다면 10초 동안 다시 실행하지 않습니다. 늦게 도착한
      누르기와 독의 동작이 겹치지 않도록 하기 위해서입니다.
    - 단추를 눌렀는데 앱과 탐색기가 응답하는데도 1.2초 안에 아무 일이 없으면 독이 직접 처리합니다. 그 실행에서 작업 표시줄 단추가
      동작하는 것을 아직 못 봤으면 한 번, 본 적이 있으면 연달아 두 번 그러면 그 실행 동안은 독의 방식만 씁니다. 앱이나 탐색기가
      바쁘면 둘이 겹치지 않도록 최대 8초까지 지켜보기만 합니다. 띄우려던 창을 Windows가 내렸으면(앱이 이미 앞에 있다고 본 경우)
      그대로 둡니다. 단추가 최소화된 창을 복원했는데 Windows가 앞 창 자리를 주지 않아 다른 창 뒤에 남으면, 누르기는 도착한
      것이므로 약 1.2초 뒤 독이 그 창을 앞으로 가져옵니다(탐색기가 바빠도 기다리지 않고, 복원 명령은 더 보내지 않음). 이 일이
      한 번 생긴 것으로는 단추 방식을 끄지 않고, 연달아 두 번이면 그 실행 동안 독의 방식을 씁니다.
    - 고정 단추로 실행했는데 10초 안에 그 앱의 창이 뜨지 않으면 다시 실행하지 않고(늦게 뜨는 앱이 두 번 실행되지 않도록),
      연달아 두 번 그러면 그 실행 동안은 고정된 앱을 독이 직접 실행합니다.
    - Windows 10식 작업 표시줄(ExplorerPatcher 등)에는 이런 단추가 없어 독의 방식만 씁니다.
    - 끄려면 독을 끈 뒤 `data\settings.ini`에 `taskbarAppButtons=0`을 넣고 다시 켭니다.
    - `data\dock.log`의 `app click:` 줄에 첫 누름(단추를 찾는 데 걸린 시간, 단추 수, 누르는 데 걸린 시간), 단추를 못 찾은 앱(찾아본
      id와 경로), 실패, 작업 표시줄 단추를 쓰기 시작하거나 그만둔 때가 남습니다. 단추를 누를 방법이 없는 Windows에서는
      `... its taskbar button was found ... but not pressed: no Invoke or Toggle ...` 한 줄이 남습니다.
  - 최소화된 창이 아직 '활성 창'으로 남아 있을 때도 다시 띄웁니다. 예전에는 이 경우 한 번 더 최소화해서, 첫 클릭이 헛돌았습니다.
  - 최소화된 창은 작업 표시줄처럼 앱에 '복원' 명령을 보내 띄웁니다. 앱이 명령을 받고도 창을 그대로 두면 Windows의 복원으로
    바로 다시 띄우고, 앱이 바빠 명령에 답하지 않는 동안에는 명령을 더 보내지 않고 최대 8초까지 기다립니다
    (최대화돼 있던 창이 복원을 두 번 받아 작아지는 일이 없도록). 기다리다 Alt+Tab이나 다른 아이콘으로 갔다가 8초 안에 다시
    눌러도 마찬가지입니다(그동안은 작업 표시줄 단추도 누르지 않음). 독은 그동안 멈추지 않습니다.
  - 창이 여럿인 앱의 창 하나가 앞에 있을 때 누르면, 화면 밖에 있는 창(모니터를 뺀 뒤 남은 위치 등)은 건너뛰고 화면 안이나
    최소화된 다른 창을 띄웁니다. 다른 창이 화면 밖 하나뿐이면 그 창으로 갑니다.
  - 크롬 프로필이나 스토어 앱처럼 한 프로그램이 독 아이콘을 여러 개 가질 때, 다른 아이콘의 창이 앞에 있다고 누른 창이 올라온
    것으로 치지 않습니다. 누른 창이 Windows에 막혀 뒤에 남으면 두 번 더 앞으로 가져오고, 그래도 안 되면 `app click:` 줄로 남깁니다.
  - 창이 뜨는 중에 아이콘을 다시 클릭하면 같은 창을 계속 띄우고, 막 뜬 창을 바로 다음 클릭(0.6초 안)이 다시 최소화하지 않습니다.
  - 독은 눌러도 활성화되지 않는 창이라, Windows가 다른 창을 앞으로 가져올 권한을 주지 않을 때가 있습니다. 그러면 창 대신
    작업 표시줄 단추만 깜빡였고, 독은 그 깜빡임을 앱의 알림으로 알고 아이콘을 튕겼습니다. 이제 권한이 없으면 아무 프로그램도
    쓰지 않는 키(0xE8)를 한 번 보내 권한을 받은 뒤 창을 앞으로 가져옵니다(RetroBar와 같은 방법). 독이 띄우던 창의 깜빡임으로는
    아이콘을 튕기지 않습니다. 같은 프로그램(같은 프로세스)의 다른 창(같은 `chrome.exe`로 도는 두 창처럼)을 번갈아 눌러도
    마찬가지입니다(예전에는 마지막에 띄운 창 하나만 기억해서, 앞의 것이 깜빡이면 아이콘이 튕겼습니다).
  - 시작·검색·빠른 설정·알림 센터가 열려 있을 때 누르면, 작업 표시줄처럼 그것을 먼저 닫고(Esc) 창을 띄웁니다. 독 창은 눌러도
    활성화되지 않는 창이라 독을 눌러도 시작·검색이 닫히지 않고, 그동안 Windows는 독이 창을 앞으로 가져오는 것을 거절하고 창만
    깜빡였습니다(예전에는 그래서 클릭이 먹지 않았습니다). 0.5초 뒤에도 그대로면 Esc를 한 번 더 보내고, 그래도 남으면 `app click:`
    줄로 남깁니다. Esc는 그 창이 아직 앞에 보일 때만 보내서, 뒤의 창(게임 메뉴 등)으로 가지 않습니다.
  - 닫힌 검색·시작 창이 화면에는 없으면서 앞 창 자리만 쥐고 있을 때(모니터가 꺼졌다 켜진 뒤에 생김)는 닫을 것이 없으므로 Esc 없이
    바로 창을 띄웁니다(mod.25). 예전에는 그것을 열린 검색으로 알고 닫히기를 1초 기다리다 클릭을 버려서, 아이콘을 눌러도 아무 일도
    없었습니다. 이때 `app click: ... is in front but not shown` 줄과, 창이 뜨면 `came up after ... over the closed Start or Search`
    줄이 남습니다. 이런 닫힌 창 때문에 숨은 독이 나오지도 않습니다('시작 메뉴와 함께 표시'는 실제로 열린 것에만).
  - 관리자 권한으로 실행한 창(관리자 권한 OBS 등)이 앞에 있으면, Windows는 일반 권한인 독이 다른 창을 그 앞으로 가져오는 것을
    막습니다. 이때는 설치된 [관리자 도우미](#관리자-권한으로-실행한-앱)가 창을 올립니다(mod.24의 도우미가 필요). 도우미가 없으면
    예전처럼 창이 올라오지 않고, `app click:` 줄이 도우미를 권합니다. 도우미가 처음 대신 올릴 때(그 뒤로는 도우미의 답이 바뀔 때만)
    `admin helper: bringing up ... over a window that runs as administrator` 줄이 남습니다.
  - 1초 넘게 걸렸거나 끝내 뜨지 않으면 `data\dock.log`에 `app click:` 줄로 걸린 시간, 앱이 바빴는지, 창의 종류·크기·상태
    (제목은 남기지 않음), 앞에 있던 프로그램과 그 관리자 권한 여부, 독이 창을 바꿀 권한을 가졌는지를 남깁니다. 끝내 뜨지 않았을
    때는 클릭 때의 권한(마지막 재시도 때와 다르면), 시작·검색을 Esc로 닫았는지, 관리자 도우미에게 맡긴 횟수도 남깁니다.
  - 아이콘 목록은 1초마다 갱신됩니다. 그 사이에 숨은 창과, 클릭이 통과하는 오버레이 창(게임 오버레이 등)은 건너뜁니다.
    보일 창이 하나도 없으면 앱을 실행합니다. 디스코드처럼 한 번만 실행되는 앱은 이때 원래 창을 다시 띄웁니다.
- **창 미리보기** – 실행 중인 앱 아이콘에 마우스를 잠깐 올려 두면 그 앱의 창들이 독 바로 안쪽(아래쪽 독이면 그 위)에 카드로 나오고,
  카드를 누르면 그 창을 띄웁니다. 창이 많으면 화살표나 마우스 휠로 넘깁니다. 정밀 터치패드나 부드럽게 도는 휠은 한 칸만큼
  돌릴 때마다 한 페이지씩 넘어갑니다(예전에는 살짝 쓸어도 첫 페이지나 끝 페이지까지 날아갔습니다).
  - 자동 숨김 독이 포인터 밑으로 올라오면(가장자리로 밀었다 바로 아이콘으로 올릴 때, 단축키나 Windows 키로 올라올 때) 포인터가
    머문 아이콘의 미리보기도 보통처럼 0.45초 뒤에 열립니다. 예전에는 다른 아이콘에 갔다 와야 열렸습니다. 아이콘을 누른 뒤, 독
    메뉴를 닫은 뒤, Esc나 바깥 클릭으로 닫은 뒤에는 전처럼 아이콘을 떠났다 와야 열립니다.
  - 최소화된 창도 기본 작업 표시줄처럼 최소화되기 직전 모습이 나옵니다. Windows가 보관해 둔 모습이라 최소화된 동안에는
    바뀌지 않습니다. 최소화된 채로 시작해 화면에 나온 적이 없는 창은 Windows가 대신 만들어 주는 카드(회색 바탕에 앱 아이콘,
    기본 작업 표시줄과 같음)가 나옵니다. 예전의 "최소화된 창 · 클릭하여 복원" 문구는 Windows가 아무 모습도 주지 않을 때만 나옵니다.
  - 미리보기를 위해 창을 복원하거나 화면을 캡처하지 않습니다. 화면 캡처를 막아 둔 창은 "미리보기가 제한된 창"으로 나옵니다.
  - 미리보기에서 창을 닫을 수 있습니다. 카드에 마우스를 올리면 오른쪽 위에 닫기(X) 단추가 나오고, 카드를 휠(가운데 버튼)로
    눌러도 닫힙니다. 기본 작업 표시줄처럼 창의 닫기 단추를 누른 것과 같아서, 저장할지 묻는 앱은 먼저 묻고(그 질문 창이 앞으로
    나옴) 닫기를 막아 둔 창은 닫히지 않습니다. 닫히는 동안 카드는 흐려지고, 창이 사라지면 카드도 빠지며 미리보기는 남은 창으로
    열려 있습니다(마지막 창이면 함께 닫힘). 2초가 지나도 남아 있으면(저장을 취소했을 때 등) 다시 누를 수 있습니다. 관리자 권한으로
    실행한 앱의 창은 다른 창 조작처럼 관리자 도우미가 닫습니다.
  - 최소화된 창은 미리보기에 처음 나올 때 `data\dock.log`에 `preview:` 줄로 Windows가 알려 준 크기와 모습·문구 중 무엇을
    보였는지 남깁니다(창 제목은 남기지 않음).
- **기존 작업표시줄 앱 자동 가져오기** – 작업표시줄에 고정해 둔 앱을 순서 그대로 가져옵니다. 스토어(MSIX) 앱(Claude, ChatGPT 등)도 포함입니다. 이후 드래그로 순서 변경·고정/해제가 됩니다.
  - 처음 켤 때(`data\pins.txt`가 없을 때) Windows가 저장한 고정 목록을 그대로 읽어, 목록 안 어느 위치에 적힌 고정이든(예전에는
    스토어 앱이 빠지거나 Chrome·카카오톡 같은 바로가기가 맨 뒤로 갈 수 있었음) 작업 표시줄과 같은 순서로 놓습니다.
  - 파일(exe나 바로가기)을 독에 끌어다 놓으면 놓은 자리에 고정됩니다(이미 고정된 앱이면 그 자리로 옮김). 고정하지 않은 채
    실행 중인 앱에 바로가기를 놓으면 그 고정은 바로가기(인자, 시작 폴더 포함)로 실행되고, 실행 중인 앱과 AUMID가 다른
    바로가기(크롬의 다른 프로필 등)는 따로 고정됩니다(작업 표시줄이 AUMID별로 단추를 나누는 것과 같음).
  - 고정된 앱 아이콘을 위로 끌어 독 밖으로 빼면 아이콘이 보이지 않게 되고, 그때 놓으면 고정이 풀립니다. 아이콘이 조금이라도
    보일 때 놓으면 순서만 바뀝니다(예전에는 'PC 상태' 패널이 들어갈 창 높이만큼, 화면 높이의 3분의 1 넘게 끌어야 풀렸음).
  - 기본 마우스 단추를 오른쪽으로 바꾼(왼손잡이) 설정에서도 아이콘을 끌어 순서를 바꾸거나 고정을 풀 수 있습니다. 누르거나
    끄는 사이에 다른 앱이 창을 열거나 닫아도 클릭과 끌어 놓기는 그대로 됩니다.
  - 아이콘을 누른 채 오른쪽 클릭 메뉴를 열거나 잠금 화면·UAC 창으로 넘어가도, 자동 숨김 독이 숨지 못하고 떠 있거나, 나중에 화면
    다른 곳에서 한 끌기가 독 아이콘 끌기가 되거나, 다음 클릭이 아이콘 이동이 되지 않습니다.
  - 버전 정보(파일 설명)가 없는 프로그램과 고정한 문서·폴더는 디스크에 적힌 철자 그대로 이름이 나옵니다(예전에는 소문자).
  - 고정 목록과 설정은 임시 파일에 다 쓰고 디스크에 내린 뒤 바꿔 넣습니다. 고정을 바꾼 직후 전원이 나가거나 디스크가 가득
    차도 마지막 목록이 남고, 저장에 실패하면 `data\dock.log`에 `pins:`·`settings:` 줄이 남습니다.

## 설정

독 끝의 톱니 버튼(또는 빈 곳 우클릭 → 설정)으로 설정 창이 열립니다. 바꾸는 즉시 독에 반영됩니다.
설정 창이 열려 있는 동안은 모든 독이 올라와 있습니다(바꾼 모양을 보면서 조정하도록). 그래서 설정 창에는 닫기 버튼만 있고,
Win+D나 '바탕화면 보기' 단추로 내려가면 그대로 닫힙니다(값은 이미 저장됨). 최소화된 설정 창이 화면에 보이지 않은 채 독을
계속 붙잡아 두는 일을 막기 위해서입니다.

- 위치: 아래 / 왼쪽 / 오른쪽 / 위 (어느 가장자리든)
- 모양: 아이콘 크기·간격, 독 두께, 화면 가장자리와의 거리, 가장자리를 따라 옮기기(슬라이더). 이 다섯 슬라이더는
  '독 크기와 위치 조정' 묶음 안에 있고, 설정 창을 열 때마다 접혀 있습니다. 묶음 제목(오른쪽의 아래 화살표)을 눌러 펼친 뒤에만 보이고
  바꿀 수 있으며, 위 화살표를 누르면 다시 접힙니다. 접혀 있는 동안에는 그 자리에서 휠을 굴리거나 눌러도 값이 바뀌지 않습니다.
  안의 값 중 기본값과 다른 것이 있으면 접힌 제목에 '바꾼 값 N개'가 나옵니다.
- 유리 질감, 시계 글자
- 동작: 확대 효과, 나타나는 속도, 숨는 속도(슬라이더). 이 세 슬라이더도 같은 방식으로 '확대 효과와 속도 조정' 묶음 안에 접혀 있습니다.
- 자동 숨김 켜기/끄기, 보조 모니터에서만 항상 표시, 독을 불러오는 단축키
  - 늘 떠 있는 독은 마우스가 근처에 없으면 유리 효과를 초당 30번 안팎으로만 갱신하고, 다른 모니터에서
    전체 화면 앱(게임·영상)이 앞에 있는 동안에는 화면 캡처를 멈추고 마지막 유리 모습을 그대로 둡니다.
    그동안 바뀌는 것은 시계와 센서 글자뿐입니다.
  - 두 모니터에 걸쳐 두 화면을 모두 채운 전체 화면 창(테두리 없는 게임·영상)이 앞에 있으면, 그 창이 덮은 모든 모니터의 독이
    비킵니다. 자동 숨김 독도 같아서 그런 창 위로 올라오지 않습니다(예전에는 한 모니터의 독만 비켰습니다).
  - 최대화한 브라우저(Chrome 등)에서 F11이나 영상의 전체 화면 단추로 띄운 전체 화면도 전체 화면으로 봅니다. 예전에는 창이 최대화
    상태로 남는다는 이유로 창으로 봐서, 마우스를 화면 끝으로 내리면 자동 숨김 독이 그 위로 올라왔습니다. 다른 모니터의 독이 뜨는
    것은 그대로입니다. 남은 한계는 아래 [알려진 한계](#알려진-한계)에 있습니다.
  - 독이 떠 있는 동안 '항상 위'로 띄운 큰 창(예: Windows Terminal의 '항상 위에 표시'를 켠 최대화·전체 화면 창)이 앞으로 와 독을 통째로
    덮으면, 독이 다시 그 창 위로 올라갑니다. 예전에는 그런 창 위에서 독의 '바탕화면 보기' 단추를 두 번 눌러 돌아오면 독이 그 창 밑에
    묻혀, 마우스를 독 자리에서 뗐다가 다시 내려야 보였습니다. 독의 일부에만 걸친 작은 '항상 위' 창(트레이 아이콘의 메뉴, 화면 속 화면
    영상 등)은 작업 표시줄 위에서처럼 그대로 독 위에 남고, Alt+Tab, 작업 보기, 시작 메뉴, 달력 같은 Windows 자신의 창 위로도 올라가지 않습니다.
  - Explorer가 다시 시작돼도(충돌, 작업 관리자의 'Windows 탐색기 다시 시작', 업데이트) 늘 떠 있는 독은 화면 자리를 곧바로 다시
    잡아, 최대화한 창이 독 밑으로 들어가지 않습니다. 독이 Explorer 작업 표시줄보다 먼저 뜨면 2초마다, 그리고 Explorer가 알리는 대로
    자리를 잡습니다.
  - OLED 모드가 켜진 모니터의 독은 이 설정과 상관없이 숨습니다.
- 버튼: 끌어다 놓아 추가·제거·순서 변경, 트레이 아이콘 표시(실험)
- Windows 시작 시 자동 실행
- 시스템: 관리자 권한 앱 창 제어(아래 [관리자 권한으로 실행한 앱](#관리자-권한으로-실행한-앱)) 등. 예전에 여기 있던 'CPU 온도 직접 읽기 (PawnIO)'는
  '센서' 페이지의 '온도 읽기'로 옮겼습니다.
- 센서 (새 페이지)
  - **온도 읽기:** 끄기 / HWiNFO Gadget(기본) / PawnIO. 모든 온도 항목에 함께 적용됩니다(아래 [CPU 온도](#cpu-온도-선택-기능)).
    - 끄기: CPU 온도와 메모리 슬롯 온도가 없고, 칸은 CPU 사용률을 보입니다. HWiNFO도 관리자 도우미도 쓰지 않습니다.
    - HWiNFO Gadget: CPU 온도, 메모리 슬롯 온도, (드라이버가 주지 않는 카드의) VRAM 온도를 HWiNFO에서 받습니다.
    - PawnIO: CPU 온도를 관리자 도우미가 PawnIO 드라이버로 읽습니다. HWiNFO는 읽지 않으므로 메모리 슬롯 온도가 없습니다.
    - 어느 쪽이든 HWiNFO·PawnIO 없이 읽히는 값(CPU·GPU 사용률, NVIDIA GPU의 온도와 VRAM 사용량, RAM, 드라이브 온도)은 그대로 나옵니다.
  - **PC 상태에 보일 항목:** CPU 온도, GPU, VRAM, VRAM 온도, RAM 슬롯 온도, SSD 토글 여섯(기본 모두 켬). '독 크기와 위치 조정'처럼 접는 묶음 안에 있고,
    접힌 머리의 '바꾼 값 N개'에 끈 토글도 셉니다. 끈 항목은 패널과 독 칸에서 빠지고 과열 알림도 울리지 않습니다.
    - CPU 온도: 끄면 독 칸에 CPU 사용률이 대신 보입니다. GPU: GPU 카드와 독 칸의 GPU 줄. VRAM: VRAM 사용량 줄과 막대(온도 줄까지). VRAM 온도: VRAM 줄
      아래의 온도 줄. RAM 슬롯 온도: 메모리 모듈마다의 온도 줄(HWiNFO에서만). SSD: 드라이브 줄(이름과 온도).
  - 바꾸면 독을 다시 만듭니다(가로 독의 창 두께가 보이는 줄에 따라 달라지므로). 페이지의 '기본값으로'는 온도 읽기와 여섯 항목을 되돌립니다.
  - `settings.ini`의 키는 `sensorSource`(0 끄기, 1 HWiNFO Gadget, 2 PawnIO)와 `showCpuTemp`, `showGpu`, `showVram`, `showVramTemp`, `showRamTemp`, `showSsd`입니다.

설정 창에는 스크롤바가 없고 휠로 페이지를 내립니다. 노트북 터치패드의 두 손가락 스크롤도 민 만큼 부드럽게 움직입니다(멈춘 자리에서
선이 흐려 보이는 것은 고치지 않은 알려진 버그, [알려진 한계](#알려진-한계)). 휠이나
스와이프로 페이지를 내리는 동안 슬라이더가 포인터 아래로 와도 그 값은 바뀌지 않습니다. 슬라이더를 휠로 바꾸려면 포인터를 그
슬라이더 위로 옮긴 다음 굴립니다(처음부터 슬라이더 위에서 굴리면 그 슬라이더가 바뀝니다). 슬라이더가 이미 끝에 있거나 한 칸이 안
되게 굴리면 아무것도 바뀌지 않고 독도 다시 만들지 않습니다.

설정은 `%LOCALAPPDATA%\Programs\LiquidDock\data\settings.ini`에 저장됩니다. 손으로 고칠 때는 독을 끈 뒤 고치고, UTF-8로
저장합니다(메모장의 'UTF-8(BOM)'도 됩니다. UTF-16은 읽지 못합니다). 숫자 자리에 `nan` 같은 잘못된 값을 적으면 그 줄은 무시하고
기본값을 씁니다.

## 기본 작업표시줄은 어떻게 되나요?

독이 실행되는 동안 Windows 기본 작업표시줄은 보이지 않게 됩니다(자동 숨김 + 화면에 그리지 않음). 독을 끄거나 제거하면 원래대로 돌아옵니다.
Windows의 자동 숨김은 모든 모니터의 작업표시줄에 한꺼번에 걸리는 설정이라, 한 모니터만 기본 작업표시줄을 늘 띄워 두는 조합은 지원하지 않습니다.
보조 모니터에 늘 보이는 막대가 필요하면 설정의 "보조 모니터에서는 항상 표시"를 켜세요.

- 독을 종료하면(독 우클릭 → 종료) 작업표시줄이 복원됩니다.
- 문제가 생기면 **Ctrl+Alt+Shift+F12** 로 즉시 종료됩니다.
- 시작 메뉴의 **"Liquid Dock - 작업표시줄 복원"** 을 실행해도 독을 끄고 기본 작업표시줄을 되돌립니다. OLED 모드였으면 원래
  배경화면도 되돌립니다. 이때 `data\dock.log`는 지워지지 않고, 방금 끝난 실행의 기록 뒤에 복원 때의 줄이 붙습니다(무엇 때문에
  복원이 필요했는지 남도록). `dock.log`를 새로 쓰는 것은 독을 켤 때뿐입니다.
- 제거할 때 Explorer가 없어 작업표시줄이나 OLED 배경화면을 되돌렸는지 확인하지 못하면, 복원 정보와 설치 파일을 남기고
  잠시 후 다시 시도하라고 알립니다.

## 트레이 아이콘 (실험 기능)

설정 → 버튼 → **트레이 아이콘 표시 (실험)** 을 켜면, Windows 작업표시줄에 보이던 트레이 아이콘이 `›` 와 네트워크·볼륨 사이에
위아래 두 줄로 들어갑니다. 어떤 아이콘을 보일지는 Windows 설정 그대로입니다
(**설정 → 개인 설정 → 작업 표시줄 → 기타 시스템 트레이 아이콘**에서 켠 것, 순서도 Windows와 같음). 나머지는 지금처럼 `›` 창에 있습니다.

- 클릭·우클릭·가운데 클릭·더블클릭이 각 프로그램에 Windows 작업표시줄에서와 같은 방식으로 전달됩니다(메뉴도 각자의 것).
  디스코드 같은 Electron 앱이 같은 GUID로 아이콘을 다시 만들면 새 번호로 클릭을 보냅니다(예전 번호로 보낸 클릭은 앱이 무시합니다).
- 흰색·검은색 한 가지 색으로 된 아이콘은 독의 글자색에 맞춰 칠해서, 밝은 배경 위에서도 보입니다.
- 원리: 프로그램은 트레이 아이콘을 "Shell_TrayWnd" 창에 보냅니다. 독이 같은 이름의 보이지 않는 창을 Explorer 것보다 앞에 두고
  아이콘을 먼저 받은 뒤, 받은 내용을 **전부 그대로 Explorer에 넘깁니다**(RetroBar와 같은 방식에, 전달을 더한 것). 그래서 `›` 창과
  알림은 그대로이고, 독이 꺼지거나 죽어도 아이콘이 사라지지 않습니다.
- 켜는 순간 실행 중인 프로그램에 아이콘을 다시 등록해 달라고 요청합니다(Windows가 탐색기를 다시 시작할 때 보내는 것과 같은 신호).
  이 요청에 응하지 않는 프로그램이나, 관리자 권한으로 실행 중이라 요청이 막힌 프로그램의 아이콘은 그 프로그램을 한 번 다시 켜야
  독에 나타납니다. 독보다 나중에 켜진 프로그램은 바로 나타납니다. 이런 프로그램은 켠 지 5초 뒤 `data\dock.log`의
  `tray host:` 줄에 이름이 남고, 받은 아이콘마다 표시 여부와 그 이유도 한 줄씩 남습니다.
- MSI Afterburner처럼 실행할 때마다 아이콘 번호가 바뀌는 프로그램도 작업표시줄에 꺼내 두었으면 독에 나옵니다. Windows는 이런
  프로그램의 설정을 처음 실행 때의 번호로 하나만 두고 나중 번호의 아이콘에도 그대로 쓰는데(앞서 그 프로그램의 설정이 있을 때입니다.
  처음 실행 때 두 창에서 거의 동시에 아이콘을 띄우면 번호마다 설정이 생길 수 있고, 그러면 아래처럼 숨깁니다), 독도 그 프로그램의 설정이 하나뿐이면
  같은 설정을 따릅니다(예전에는 번호까지 같은 설정만 찾아서 "not shown (no settings entry yet)"으로 숨겼습니다). 그 프로그램의
  설정이 여럿이면 Windows가 어느 것을 쓰는지 알 수 없어 예전처럼 숨깁니다.
- 프로그램이 지운 아이콘은 그 뒤에 그 프로그램이 갱신을 보내도 독에 다시 나타나지 않습니다(Windows가 모르는 아이콘이면 독도 만들지 않음).
  단, 그 갱신이 마침 Explorer가 다시 시작되거나 응답하지 않는 순간에 오면 독에 아이콘이 생기고, 그 뒤 Explorer가 모르는 아이콘이라고
  답해도 그 프로그램이 아이콘을 지우거나 끝날 때까지 남습니다(고치지 않은 알려진 버그, 아래 [알려진 한계](#알려진-한계)).
- 작업표시줄 창을 이름으로 찾는 다른 프로그램은 독의 창을 찾게 됩니다. FluentFlyout은 아래 연동으로 독에 들어가고, 그 밖의
  작업표시줄 위젯은 지금처럼 보이지 않습니다. 이상하면 이 옵션을 끄세요. 끄면 즉시 원래대로 돌아갑니다.
- 관리자 권한으로 실행된 프로그램의 아이콘은 Windows 보안 정책 때문에 클릭이 전달되지 않을 수 있습니다.
- 독은 관리자 권한으로 시작되면(관리자 터미널에서 실행 등) 탐색기를 통해 일반 권한으로 다시 시작합니다. 로그온 자동 실행과
  같은 권한입니다. Windows는 일반 프로그램이 관리자 권한 프로그램의 창에 손대지 못하게 막아서, 관리자 권한 독에는
  FluentFlyout 위젯이 들어오지 못하고 일반 프로그램의 트레이 클릭도 일부 막히기 때문입니다. 관리자 권한을 유지하려면 `--keep-admin`을
  붙여 실행하세요. 그때도 일반 프로그램의 아이콘은 받고, 다른 프로그램이 독을 거쳐 관리자 프로그램을 조작하지 못하도록 클릭은
  트레이 아이콘이 쓰는 형태(프로그램이 정한 메시지, 최상위 창이나 메시지 전용 창)로만 전달합니다. 다른 창 안에 들어간 창(컨트롤)으로는
  전달하지 않습니다.
- 트레이 아이콘이나 FluentFlyout 연동을 끄는 순간 FluentFlyout이 응답하지 않아 독이 기다리다 포기했더라도, 그 프로그램이 돌아온 뒤
  다시 켜면 아이콘과 위젯이 다시 독에 나옵니다. 그사이 다른 설정을 하나 더 꺼도 독이 다시 오래 멈추지 않습니다.
- 자원: 아이콘이 바뀔 때만 일하고, 0.1초마다 창 순서를 한 번 확인하는 정도입니다. 아이콘 그림은 개당 수 KB입니다.

## FluentFlyout 연동

[FluentFlyout](https://github.com/unchihugo/FluentFlyout)이 실행 중이면 독이 알아서 이어 붙입니다(설정 → 버튼 → **FluentFlyout 연동**,
기본 켜짐). 두 프로그램의 코드는 섞이지 않습니다. FluentFlyout이 없거나 꺼져 있으면 독은 지금과 똑같습니다.

- **작업 표시줄 위젯·비주얼라이저**: 독 유리 안, 시작 버튼 왼쪽 칸에 들어갑니다. 위젯은 FluentFlyout 자신의 창 그대로라
  클릭(미디어 Flyout 열기), 재생 버튼, 우클릭 메뉴, 휠 볼륨, 툴팁, 애니메이션이 모두 FluentFlyout 설정대로 동작합니다.
  칸의 너비는 위젯 너비를 따라 부드럽게 바뀌고(곡이 바뀔 때마다 독이 흔들리지 않도록 12px 단위), 독과 함께 올라오고 내려갑니다.
  위젯을 눌러도 쓰던 창의 포커스는 그대로입니다(독 아이콘을 누를 때와 같음).
- **재생 중인 미디어가 없을 때 완전히 숨기기**: 이 옵션이 켜져 있으면 재생 중인 미디어가 없을 때 칸이 닫혀 독이 원래 길이로
  돌아가고, 재생이 시작되면 다시 열립니다. "일시 정지하면 숨기기"도 같은 식입니다. FluentFlyout의 앱 필터(허용·차단 목록)도 따릅니다.
  앱 이름은 FluentFlyout과 같은 순서로 정합니다. 실행 중인 프로그램의 설명, 없으면 그 창 제목, 실행 중인 프로그램이 없으면
  Windows의 앱 이름(스토어 앱, Firefox 등)입니다. 그래서 허용 목록에 넣은 스토어판 플레이어나 Firefox가 재생하는 동안 칸이 닫히지
  않습니다. 필터를 켠 직후(또는 FluentFlyout을 다시 켠 직후) 5초쯤 안에는 아직 이름을 모르는 앱을 재생 중으로 봅니다.
  브라우저처럼 곡이 바뀔 때 미디어 세션을 잠깐 끊었다 다시 여는 앱 때문에 칸이 깜빡이지 않도록, "재생 중인 미디어 없음"은
  1.5초 동안 이어져야 반영합니다(재생 시작은 바로 반영). 다만 독을 켜거나 FluentFlyout을 처음 찾았을 때 받은 첫 목록은 바로
  반영해서, 아무것도 재생하지 않을 때 빈 칸이 1초쯤 열렸다 닫히지 않습니다.
- **미디어 Flyout · 현재 재생 정보 Flyout**(볼륨·잠금 키 Flyout 포함): 독이 떠 있을 때 열리면 위젯 위로 정렬된 뒤, FluentFlyout의
  등장 애니메이션이 끝나면 독 유리 위로 올라와 자리 잡습니다(그 전까지는 유리 뒤에 있습니다). 볼륨 Flyout처럼 위에 겹쳐 뜨는 것은
  같이 움직입니다. 그 위에 마우스가 있는 동안 독은 숨지 않습니다. 독이 숨어 있으면 FluentFlyout이 정한 위치 그대로 뜨고,
  화면 위쪽으로 설정한 Flyout은 건드리지 않습니다.
- **어느 모니터의 독에 들어가나**: FluentFlyout의 **작업 표시줄 위젯 → 작업 표시줄 위젯 모니터**를 따릅니다(FluentFlyout의 번호:
  주 모니터가 "1", 나머지는 왼쪽부터 "2", "3"). [시스템] 페이지의 "모니터"는 Flyout이 뜨는 모니터라 위젯과는 별개입니다.
  - 독은 FluentFlyout의 설정 파일(바뀌면 2초 안에 다시 읽음)과, FluentFlyout이 실제로 위젯을 넣은 작업표시줄을 함께 봅니다.
    FluentFlyout이 위젯을 다른 모니터의 (숨겨진) 기본 작업표시줄에 넣으면 그것이 FluentFlyout의 선택이므로 독도 바로 그 모니터로 옮깁니다.
    설정 파일이 아직 저장되지 않았거나 예전 값이어도 따라갑니다. 단, FluentFlyout을 "1"(주 모니터)로 바꾼 경우는 설정 파일만이
    알려 줍니다(FluentFlyout이 그때는 독 창을 그대로 쓰기 때문). FluentFlyout은 설정을 바꾸면 0.5초 뒤 자동 저장합니다.
  - 모니터가 여러 대인데 Windows의 '모든 디스플레이에 작업 표시줄 표시'가 꺼진 PC에서는 FluentFlyout이 위젯을 늘 주 작업
    표시줄에 넣으므로, 독은 위젯이 들어간 곳 대신 설정 파일을 따릅니다(예전에는 독을 켤 때 위젯이 주 모니터 독으로 잘못 갔습니다).
  - 독 우클릭 메뉴에 **"FluentFlyout 위젯: N번 모니터 - 설정 열기..."**가 있습니다. 지금 위젯이 가는 모니터를 FluentFlyout의 번호로
    보여 주고, 누르면 FluentFlyout 설정 창을 엽니다.
  - 위젯 위치(왼쪽·가운데·오른쪽)와 상관없이 시작 버튼 왼쪽 칸에 놓입니다. 독이 화면 왼쪽·오른쪽 가장자리에 있으면 위젯은
    들어가지 않습니다(Flyout 정렬도 위·아래 독만).
  - 주 모니터의 독이 자동 숨김이면 위젯도 그 독이 나올 때만 보입니다.
- FluentFlyout은 디스플레이나 작업 영역이 바뀔 때마다(모니터 연결, 늘 보이는 독이 자리를 잡을 때, OLED 모드 전환 등) 위젯 창을
  새로 만듭니다. 그동안 독은 칸을 닫지 않고 최대 3초 기다렸다가 새 위젯 창을 바로 그 자리에 받습니다(독 길이가 줄었다 늘어나지 않음).
- 원리: FluentFlyout은 위젯을 첫 번째 "Shell_TrayWnd" 창 안에 넣습니다. 독의 트레이 호스트 창(위의 트레이 아이콘과 같은 창)이
  그 자리에 있다가, 독이 위젯 칸 위에 그 창을 투명하게 놓아 줍니다. 그래서 트레이 아이콘 옵션이 꺼져 있어도 FluentFlyout이
  실행 중이고 위젯이 켜져 있으면 이 창이 돌아갑니다(아이콘을 다시 등록하라는 요청은 보내지 않고, 받은 내용은 그대로 Explorer에).
  독이 종료되면 위젯은 기본 작업표시줄로 돌아갑니다.
  FluentFlyout 위젯은 투명 배경 WPF 창(레이어드 창)이라, 자식 창일 때는 부모 창에 그림 표면이 있어야 화면에 나옵니다.
  그래서 이 창은 표면을 갖되 스스로는 완전히 투명하게(알파 0) 칠하고, 위젯만 그 위에 그려집니다. 독이 혼자 앞으로 올라와
  위젯을 덮으면 0.1초 안에 위젯 창을 다시 위로 올립니다.
- 확대 효과로 칸이 움직여도 위젯이 칸을 따라갑니다(mod.29).
  - FluentFlyout 위젯은 WPF 창입니다. WPF는 프레임마다 위젯이 화면 어디 있는지 읽고, 그린 프레임을 보일 때 위젯을 그 자리에 놓습니다.
    그 사이에 독이 위젯을 담은 창을 옮기면 위젯은 예전 자리에 놓이고, 다음 프레임부터는 그 자리를 다시 읽어 그대로 둡니다.
  - 예전에는 확대 중에 위젯이 자리에서 벗어나 있는 시간이 81%였고, 한 번에 3초까지 이어졌습니다. FluentFlyout이 1.5초마다 바로잡기를
    기다렸고, 그동안 위젯 왼쪽이나 오른쪽(앨범 아트·제목, 또는 다음 단추·비주얼라이저)이 잘려 보였습니다. 독이 어긋난 위젯을 따라 칸을
    옮겨, 몇 초씩 더 크게 잘리기도 했습니다.
  - 이제 독은 위젯이 어긋나면 바로 제자리로 되돌리고, 잠시 뒤 다시 보고 또 어긋났으면 다시 되돌립니다. 위젯을 담은 창의 잘린 모양도
    바로 따라갑니다.
  - 테스트 PC에서 잰 값: 벗어난 시간 0.4 ~ 1.9%, 어긋남은 2 px 이하, 한 번에 길어야 0.1초입니다.
  - 위젯 영역을 잠깐 읽지 못한 순간에도 칸이 튀지 않습니다.
  - 되돌릴 때 `tray host: the widget was X,Y off ...` 줄이 처음 세 번과, 그 뒤 100번마다 남습니다.
  - 비용: 되돌리기는 위젯이 어긋났을 때만, 별도 스레드에서 합니다(위젯이 제자리에 있으면 아무것도 보내지 않음). FluentFlyout과 독의 CPU
    사용은 눈에 띄게 늘지 않았습니다.
- 위젯은 독처럼 화면 캡처(스크린샷·녹화)에 찍히지 않습니다. 독 유리가 위젯을 비쳐 보이게 하지 않으려는 것입니다.
- 위젯 글자색은 FluentFlyout이 Windows 테마(다크/라이트)에 맞춰 정합니다. 밝은 배경 위 독에서 잘 안 보이면 Windows 테마를 바꾸거나
  FluentFlyout의 "배경 블러"를 켜 보세요.
- 자원: FluentFlyout을 찾는 일은 2초에 한 번(위젯 창을 새로 만드는 동안만 0.1초마다, 최대 3초), 미디어 세션 목록은 FluentFlyout의
  "재생 중인 미디어가 없을 때 완전히 숨기기"가 켜져 있을 때만, 바뀔 때(놓친 변화는 5초마다), 모니터 목록은 디스플레이가 바뀔 때(그리고
  5초마다) 확인합니다. "완전히 숨기기"가 꺼져 있거나 FluentFlyout이 끝나면 미디어 스레드는 깨어나지 않습니다(예전에는 FluentFlyout을
  한 번 찾으면 독이 끝날 때까지 5초마다 깨어남). 다시 켜면 1초 안에 목록을 받아 칸을 맞추고, 그동안 칸은 마지막 모습 그대로입니다.
  위젯은 FluentFlyout이 그립니다. FluentFlyout이 켜져 있고 "완전히 숨기기"와 앱 필터를 함께 쓸 때만, 새 미디어 앱이 나타나면 그 이름을
  미디어 스레드에서 한 번 찾습니다(독의 화면 스레드는 하지 않음). `fluentflyout: media playing` / `nothing playing` 줄도 "완전히 숨기기"가
  켜져 있을 때만 남습니다.
- 독이 관리자 권한으로 실행 중이면 FluentFlyout이 위젯을 독 창에 넣지 못합니다(Windows 보안 정책). 독은 그렇게 시작되면 스스로
  일반 권한으로 다시 시작합니다(`--keep-admin`이면 그대로). 관리자 권한으로 실행한 앱의 창은 아래
  [관리자 권한으로 실행한 앱](#관리자-권한으로-실행한-앱)을 보세요.
- `data\dock.log`의 `fluentflyout:` 줄에 찾은 설정 파일, 위젯이 들어갈 모니터, 위젯 창이 지금 어디 있는지, 칸이 열리고 닫힌
  이유가 남습니다. 몇 초가 지나도 위젯이 독 창으로 오지 않으면 그 이유도 한 줄 남습니다. 앱 필터 때문에 앱 이름을 찾았으면
  `fluentflyout: media app ... - FluentFlyout's name for it "..."` 줄이 남습니다. 칸에 위젯이 처음 보일 때
  `tray host: widget seen` 줄에 창 위치·크기, 위젯 영역, 잘린 영역, 그리는 방식(레이어드 여부), 독보다 위에 있는지가 남습니다.

## 관리자 권한으로 실행한 앱

OBS처럼 관리자 권한으로 실행한 앱의 창은, Windows가 일반 권한 프로그램에게 복원·최소화·닫기를 허락하지 않습니다(UIPI).
독은 FluentFlyout 위젯과 트레이 아이콘 때문에 일반 권한으로 실행되므로, 그런 창은 선택 기능인 **관리자 도우미**가 대신 처리합니다.
다른 앱의 창은 독이 직접 다룹니다(관리자 권한 창이 앞에 있을 때는 빼고, 아래).

mod.24부터 도우미는 관리자 권한 창이 앞에 있을 때 독에서 누른 일반 창을 그 앞으로 가져오는 일도 합니다. Windows는 일반 권한인
독이 관리자 권한 창에게서 앞 창 자리를 빼앗는 것을 막기 때문입니다(독이 권한을 받으려 보내는 키도 그 창에는 닿지 않음). 도우미는
먼저 그냥 앞으로 가져와 보고, 안 되면 독에서 막 클릭했을 때만(마지막 입력이 2초 안이고 마우스 아래 창이 독의 것일 때) 자기 키로
권한을 받아 다시 시도합니다(아래). 최소화된 창은 독이 먼저 복원 명령을 보내고,
창이 올라온 다음에 도우미에게 맡깁니다(복원이 두 번 가면 최대화 창이 작아지므로).

- 관리자 권한 앱의 아이콘을 처음 누르면 도우미를 설치할지 묻습니다. 설치하면 Windows 확인 창이 한 번 뜨고, 그 뒤로는 확인 없이
  독과 함께 실행됩니다. 도우미가 바뀐 새 독을 설치할 때는 다시 한 번 뜹니다(아래). 설정 → 시스템 → **관리자 권한 앱 창 제어**에서 끄고 켤 수 있습니다
  (힌트 "OBS 등의 창 · 설치·업데이트할 때마다 Windows 확인 한 번").
  - 질문이 떠 있는 동안 독을 다시 눌러도(더블클릭 포함) 질문은 하나만 뜹니다. 그사이 누른 앱은 "예"면 도우미가 뜨는 대로 누른
    순서대로 처리하고, "아니요"면 처리하지 않습니다.
  - 설치된 도우미가 독의 것과 같고 예약 작업도 있으면, '관리자 권한 앱 창 제어'를 켜거나 설정 → 센서의 '온도 읽기'에서 PawnIO를 골라도 확인 창 없이 바로
    켜집니다(예전에는 PawnIO를 켤 때마다 다시 설치하며 확인 창이 떴습니다). 다르거나 예약 작업이 없으면 설치하며 확인 창이 한 번 뜹니다.
- **설치 프로그램이 설치된 도우미를 바꿉니다 (mod.33부터).** `LiquidDock-Setup.exe`는 `%ProgramFiles%\LiquidDock`에 도우미가 설치돼 있으면 Setup에 든
  도우미와 바이트 단위로 비교하고, 다르거나 예약 작업이 없으면 Windows 확인 창(UAC)을 한 번 띄워 도우미를 바꿉니다(`/silent`로 설치해도 뜹니다).
  도우미를 설치하지 않은 PC에서는 묻지 않습니다.
  - 도우미 파일에는 버전이 들어 있어 새 판마다 바이트가 달라지므로, 사실상 도우미가 설치된 PC는 업데이트마다 확인 창이 한 번 뜹니다. 같은 소스라도 다른
    PC에서 빌드한 설치 프로그램이면 한 번 더 뜰 수 있습니다.
  - 확인 창에 답할 때까지 독은 다시 뜨지 않고, 그동안은 Windows 작업표시줄이 보입니다. 거절하거나 바꾸지 못해도 독 설치는 끝나고, 도우미는 이전 판 그대로
    돕니다. `/silent`가 아니면 "관리자 도우미를 업데이트하지 못했습니다" 창이 뜨고, 다음에 설치할 때 다시 묻습니다.
  - 바꿀 때는 돌던 도우미를 멈추고 새 파일을 복사합니다. 파일이 아직 잡혀 있어 덮어쓸 수 없으면 옛 파일을 `LiquidDockSensors.exe.old`로 비키고 복사한 뒤,
    그 이름으로 돌던 옛 도우미까지 멈춥니다. `.old`는 곧바로 지우고, 못 지우면 다음 재부팅 때 지웁니다. 복사가 끝내 안 되면 옛 파일을 제자리로 되돌립니다.
    이 길(확인 창, 거절, `.old`)은 아직 실제 설치로 확인하지 않았습니다.
- mod.32까지의 설치 프로그램은 도우미를 바꾸지 않았습니다(창 서비스가 없는, mod.10보다 오래된 도우미만 독이 바꾸자고 물음).
  mod.23은 도우미 쪽도 고쳤고(파이프를 열었다 바로 닫는 프로그램이 있어도 창 제어가 멈추지 않음, 낮은 무결성 프로그램은
  파이프를 열 수 없음, 모든 프로세서가 바쁠 때도 창 요청에 답함), mod.24도 도우미를 바꿨습니다(관리자 권한 창 앞으로 일반 창을
  가져오기). 이제는 새 독을 설치할 때 위처럼 바뀝니다. 확인 창을 거절했거나 설치 프로그램 없이 바꾸려면, 관리자 권한 PowerShell에서
  `& "$env:LOCALAPPDATA\Programs\LiquidDock\LiquidDockSensors.exe" --install`을 한 번 실행합니다(돌던 도우미를 멈추고 새 파일로
  바꾼 뒤 다시 시작함). '관리자 권한 앱 창 제어'를 껐다 켜는 것으로는 같은 도우미가 이미 있으면 바뀌지 않습니다.
  - 설치된 도우미가 mod.24보다 오래됐으면, 도우미가 관리자 권한 창 앞으로 창을 처음 가져오려 할 때 `data\dock.log`에 한 번
    `admin helper: the installed helper is older than 0.2.0-mod.24 and cannot take the front itself - update it (LiquidDockSensors.exe --install, as administrator)`
    줄이 남습니다. 옛 도우미가 창을 올리지 못하면 독이 자기 방법으로도 한 번 더 해 봅니다. 독이 도우미를 바꾸자고 스스로 묻지는 않습니다.
  - `--install`은 창 없이 끝나므로, 실행해도 화면에는 아무 일도 일어나지 않는 것처럼 보입니다. PowerShell은 끝나기를 기다리지 않고
    종료 코드도 남기지 않습니다(도우미가 창 프로그램이므로). 그래서 종료 코드로는 볼 수 없고, 아래 해시는 `sensors.log`에 새
    `window service up`이 생긴 뒤에 봅니다(실행 직후에 보면 아직 복사 전일 수 있습니다).
    - 두 사본이 같습니다: `Get-FileHash "$env:LOCALAPPDATA\Programs\LiquidDock\LiquidDockSensors.exe", "$env:ProgramFiles\LiquidDock\LiquidDockSensors.exe"`의
      두 해시가 같으면 바뀐 것입니다. 복사본은 원본의 파일 시각을 그대로 가지므로, 파일 시각으로는 알 수 없습니다.
    - `%ProgramFiles%\LiquidDock\sensors.log`에 `window service up`이 있습니다.
    - `tests\run_admin_live.bat`은 두 사본의 버전(`installed helper ..., the dock's own copy ...`, 바뀌었으면 둘 다 새 독의 버전)과 도우미가 제대로 답하는지를 함께 보여 줍니다.
- 도우미는 CPU 온도용과 같은 프로그램(`LiquidDockSensors.exe`)입니다. 관리자만 바꿀 수 있는 `%ProgramFiles%\LiquidDock`에 복사되어
  작업 스케줄러로 실행되고, 독이 꺼지면 30~35초 뒤 끝납니다. '온도 읽기'가 PawnIO가 아니면(또는 CPU 온도를 숨기면) 센서는 읽지 않습니다.
  - 창 제어만 맡는 동안에는 5초마다 깨어납니다(예전에는 1초마다, 시간당 3,600번 → 720번). 창 요청은 그사이에도 바로 처리합니다.
    PawnIO로 CPU 온도를 읽는 동안은 예전처럼 1초마다 읽고, 다른 것으로 바꾸면 1초 안에 PawnIO 드라이버도 놓습니다(예전에는 독이 꺼질 때까지 쥐고 있음).
  - 게임이나 빌드가 모든 프로세서를 쓰는 동안에도 창 요청에 바로 답합니다. 도우미는 작업 스케줄러가 보통 미만 우선순위로 띄우는데,
    프로세스 등급은 그대로 두고 도우미의 메인 스레드(창 요청과 센서 읽기를 함께 함)를 독과 같은 수준으로 올렸습니다(예전에는 그럴
    때 가끔 독이 1.5초를 기다린 뒤 응답 없음으로 끝냄). 쉬는 동안의 비용은 늘지 않습니다. PawnIO로 읽는 동안의 1초 샘플도 같은
    수준에서 돕니다.
- 하는 일은 독이 요청한 창의 **복원·앞으로 가져오기, 최소화, 닫기** 세 가지뿐입니다. 작업 표시줄 단추가 있는 앱 창만 대상이고,
  같은 사용자로 실행된 `LiquidDock.exe`의 요청만 받으며(네트워크로는 불가), 독도 그 폴더에 설치된 도우미에게만 요청합니다.
  - 앞으로 가져오기에서 도우미가 스스로 앞 창 권한을 받는 것(아무 프로그램도 쓰지 않는 키 0xE8, 0.1초까지 다시 시도)은 독에서 막
    클릭했을 때만입니다. 이름만 `LiquidDock.exe`인 같은 사용자의 다른 프로그램이 도우미로 관리자 권한 창 앞에 창을 끌어오지 못하게
    하려는 것입니다(마우스 밑에 작은 투명 창을 두는 식으로는 뚫릴 수 있어 완전한 막음은 아닙니다). 앞 창의 입력에 붙는 방법
    (AttachThreadInput)은 쓰지 않습니다. 그 프로그램이 멈추면 도우미도 함께 멈출 수 있기 때문입니다.
- 설치를 거절하면 지금처럼 독이 직접 시도합니다(관리자 권한 창은 반응하지 않고, 관리자 권한 창이 앞에 있으면 다른 창도 올라오지
  않음). Alt+Tab은 언제나 됩니다.
- `data\dock.log`의 `admin helper:` 줄에 도우미 상태가, `%ProgramFiles%\LiquidDock\sensors.log`에 도우미가 거절한 요청이 남습니다.

## CPU 온도 (선택 기능)

Windows는 CPU 온도를 일반 프로그램에 주지 않기 때문에, CPU 온도는 HWiNFO에서 받아 오거나 드라이버로 직접 읽습니다.
어느 쪽을 쓸지는 설정 → 센서의 **온도 읽기**(끄기 / HWiNFO Gadget / PawnIO)나 시스템 모니터 칸의 우클릭 메뉴에서 고릅니다. 한 번에 하나만 쓰고,
고른 쪽이 아닌 곳은 읽지 않습니다(예전에는 PawnIO를 켜 두어도 HWiNFO 값이 있으면 그쪽을 먼저 썼습니다).

**HWiNFO에서 받아 오기 (드라이버·관리자 권한 불필요, '온도 읽기: HWiNFO Gadget', 기본값)** – RTSS 오버레이처럼 HWiNFO가 읽은 값을 그대로 씁니다.
메모리 슬롯 온도와, 드라이버가 주지 않는 카드의 VRAM 온도도 이 방법에서만 나옵니다.

1. HWiNFO 센서 창 → 톱니(Configure Sensors) → **HWiNFO Gadget** 탭 → **Enable reporting to Gadget** 체크
2. CPU 온도 항목(AMD `CPU (Tctl/Tdie)`, Intel `CPU Package`)을 골라 **Report value in Gadget** 체크
   - 한국어 HWiNFO는 항목 이름도 한국어입니다(예: `코어 온도`). `[CPU #0]` 센서 아래의 온도 항목이면 이름과 상관없이 씁니다.
     `TjMAX까지의 거리` 항목은 온도가 아니라 여유분이라 쓰지 않습니다.
   - 같은 센서 아래에 있어도 내장 그래픽 온도(Intel `CPU GT Cores (Graphics)`, AMD APU의 GFX 온도)는 GPU 온도라 쓰지 않습니다.
     그것만 체크했다면 CPU 온도가 비고 HWiNFO 안내가 뜹니다. `hwinfoCpuLabel=`에 그 이름을 적으면 그대로 씁니다.
3. (메모리 온도, 선택) 같은 탭에서 메모리 센서 `DDR5 DIMM [#1]`, `DDR5 DIMM [#3]`처럼 꽂힌 모듈마다 `SPD Hub Temperature` 항목을
   골라 **Report value in Gadget** 체크
   - 한국어 HWiNFO는 항목 이름이 `SPD Hub 온도`입니다. 센서 이름 끝의 `(P0 CHANNEL A/DIMM 1)` 같은 위치로 'PC 상태' 패널의
     슬롯(A2 등)에 맞춥니다. 맞출 수 없으면 슬롯 없이 `RAM 1`, `RAM 2`로 나옵니다.
   - 온도가 아닌 값(메인보드의 'DIMM' 전압 등)과 모듈의 전원 칩(PMIC) 온도는 쓰지 않습니다. DDR4의 `DIMM[n] Temperature` 항목도 읽도록 했지만 실제 PC에서 확인하지는
     못했습니다.
4. (VRAM 온도, 선택) 같은 탭에서 그래픽 카드 센서(`dGPU [#0]: NVIDIA GeForce ...`처럼 `GPU [#n]`이 든 이름)의 **GPU 메모리 접합 온도**
   (영어 `GPU Memory Junction Temperature`)를 골라 **Report value in Gadget** 체크
   - GPU가 여럿이면 독의 GPU 카드와 같은 이름의 센서를 씁니다. 그 카드에 메모리 온도가 없으면 다른 GPU의 것을 빌리지 않습니다.
   - NVIDIA 이외의 GPU는 사용량도 HWiNFO에서 받아 옵니다(`GPU Memory Allocated`, `GPU D3D Memory Dedicated`, AMD의 `GPU Memory Usage` 등).
     공유 메모리나 남은 양은 쓰지 않습니다. 테스트한 PC에서는 그 길을 쓰지 않아 실제 키로 확인하지 못했습니다.

HWiNFO가 실행 중이면 독이 몇 초 안에 그 값을 표시합니다. 여러 CPU 온도를 보고하고 있다면
`%LOCALAPPDATA%\Programs\LiquidDock\data\settings.ini`의 `hwinfoCpuLabel=`에 쓸 항목 이름을 적고 독을 다시 켜면 그 항목을 씁니다.
무료 버전에서 12시간 제한이 걸리는 HWiNFO의 공유 메모리 기능과는 별개의 설정입니다.
HWiNFO를 끄면 레지스트리에 마지막 값이 남지만 20초쯤 뒤부터 쓰지 않습니다. HWiNFO는 값이 바뀔 때만 레지스트리에 쓰므로(8.54에서
확인), 온도가 한동안 그대로여도 HWiNFO가 켜져 있는 한 그 값을 계속 씁니다(예전에는 60초 넘게 그대로인 값을 버려 CPU 온도가
사라질 수 있었음). HWiNFO가 켜져 있는지는 한 번 찾은 HWiNFO 프로세스를 쥐고 묻습니다(예전에는 5초마다 프로세스 목록 전체를
읽음). HWiNFO를 끈 뒤 Windows 시계가 뒤로
가도(시간 동기화, 수동 변경) 그 값이 살아 있는 값처럼 남지 않고, HWiNFO가 설정을 바꾸며 그 키를 지웠다 다시 만들어도 독이 멈추지
않고 새 키를 읽습니다.

**직접 읽기 (PawnIO 드라이버, '온도 읽기: PawnIO')**

1. [PawnIO](https://pawnio.eu/) 드라이버 설치 (LibreHardwareMonitor·FanControl 등이 쓰는 서명된 오픈소스 드라이버)
2. 설정 → 센서 → 온도 읽기에서 **PawnIO**를 고르거나, 독 맨 끝 칸 우클릭 → **온도 읽기: PawnIO (관리자 도우미)**
   - 관리자 도우미가 없거나 독의 것과 다르면 설치하며 관리자 확인이 한 번 뜹니다. 같은 도우미가 이미 설치돼 있으면 확인 없이 바로 켜집니다.
   - PawnIO가 설치돼 있지 않으면 안내 창이 뜨고 PawnIO 페이지를 열 수 있습니다. 설치한 뒤 '온도 읽기'에서 PawnIO를 다시 고릅니다.

이 방법에서는 HWiNFO를 읽지 않습니다. 그래서 메모리 슬롯 온도가 없고, VRAM 온도는 드라이버가 그 온도를 주는 카드에서만 나옵니다.
그 뒤로는 확인 창 없이 자동으로 켜집니다(도우미가 바뀐 새 독을 설치할 때만 다시 한 번). 지원: AMD Ryzen, Intel. GPU 온도는 NVIDIA만 지원합니다.
온도를 읽지 않아도('온도 읽기: 끄기') 사용량 표시를 포함한 나머지 기능은 모두 동작합니다.

일부 게임의 안티치트는 커널 드라이버를 싫어할 수 있습니다. PawnIO는 선택 사항이니, 그런 게임을 하신다면 설치하지 않거나 '온도 읽기'를 HWiNFO Gadget이나 끄기로 두세요.

**예전 설정에서 올라올 때 (mod.33):** 예전의 'CPU 온도 직접 읽기 (PawnIO)'를 꺼 두었던 PC(기본값)는 HWiNFO Gadget이 됩니다. 켜 두었던 PC는 새 독을 처음
켤 때 한 번 정합니다. PawnIO가 설치돼 있고 HWiNFO가 그때 CPU 온도를 주지 않으면 PawnIO, 아니면 HWiNFO Gadget입니다(예전 독은 그런 PC에서 HWiNFO 값을
보였으므로, 업데이트 뒤에도 CPU 온도가 사라지지 않게). 정한 쪽은 `data\dock.log`에 `sensors: settings from before the source, PawnIO switch on - …` 줄로
남고 `settings.ini`의 `sensorSource=`로 저장됩니다. 다르게 쓰고 싶으면 설정에서 바꿉니다.

## 알려진 한계

- 최소화된 창의 미리보기는 최소화되기 직전 모습이라 최소화된 동안 바뀐 내용은 나오지 않습니다(기본 작업 표시줄과 같음).
  화면에 나온 적이 없는 창은 앱 아이콘 카드로 나옵니다.
- 일반 Windows 11에서 숨겨진 아이콘 창은 Windows가 정한 위치(오른쪽 아래)에 열립니다.
- 시작 버튼은 Windows 11 작업 표시줄의 시작 단추를 UI 자동화 ID(`StartButton`)로 찾습니다. 바뀐 Windows에서 못 찾거나 눌러도
  시작 메뉴가 안 뜨면 독이 알아서 셸 요청으로 돌아갑니다.
- 시작 메뉴를 여는 셸 인터페이스는 문서화되지 않은 것입니다(RetroBar·ExplorerPatcher와 같은 방식). 바뀐 Windows에서는 요청이
  거절되므로 독이 알아서 Win 키 방식으로 돌아갑니다.
- Windows 10, Intel CPU 온도는 개발자 PC에서 직접 검증하지 못했습니다. 문제가 있으면 Issues에 남겨 주세요.
- 최대화한 창에서 띄운 전체 화면은, 창이 최대화된 채로 제목 표시줄과 크기 조절 틀이 없어지고 창과 그 안쪽 영역이 모니터와 정확히
  같을 때만 전체 화면으로 봅니다(mod.24, 최대화한 Chrome에서 F11과 영상 전체 화면 단추는 실기기에서 확인). 다음은 여전히
  전체 화면으로 보지 않아 자동 숨김 독이 그 위로 올라옵니다.
  - 최대화한 상태에서 테두리 없는 팝업 창(`WS_POPUP`)으로 바뀌어 전체 화면이 되는 앱입니다(Windows Terminal의 F11이 그럴 것으로
    보이나 확인하지 않았습니다).
  - 최대화한 테두리 없는 팝업 창(Qt·WPF 앱)입니다. Windows가 모니터에 딱 맞추므로 전체 화면과 구별할 수 없어, 일부러 창으로 봅니다.
  - 창이 모니터와 1픽셀 어긋나는 배율(175% 등)의 전체 화면입니다(전과 같습니다).

  최대화한 Firefox와 Edge의 F11은 확인하지 않았습니다.
- 시작·검색이 열린 채 독 아이콘을 누를 때, 검색에 글자를 친 상태처럼 Esc 한 번에 닫히지 않는 경우는 실기기에서 다 보지 못했습니다
  (Esc는 두 번까지 보냄). 닫히는 사이 다른 프로그램으로 가면 독은 그 창을 '돌아온 앞 창'으로 보고 누른 창을 올립니다.
- 닫힌 검색·시작 창이 앞 창 자리를 쥐고 있을 때 Windows가 독이 띄우는 창을 그 앞으로 보내 주는지는 아직 실기기에서 보지 못했습니다.
  막히면 `app click: could not bring up ... in front: searchhost.exe ... cloaked` 줄이 남습니다. 그때는 아무 창이나 한 번 클릭하거나
  Alt+Tab으로 넘어가면 풀립니다.
- 관리자 도우미가 없는 PC(설치를 거절했을 때 등)에서는 관리자 권한 창이 앞에 있는 동안 독 아이콘으로 다른 창을 띄울 수 없습니다
  (`app click:` 줄이 도우미를 권함). Alt+Tab은 됩니다.
- 최대화한 창(PowerShell을 띄운 Windows Terminal 등) 아래로 배경화면이 얇게 보일 수 있습니다. 독은 기본 작업표시줄을 Windows의
  자동 숨김으로 숨기는데, 이런 앱은 자동 숨김 작업표시줄을 마우스로 불러낼 수 있게 화면 가장자리에 1~2픽셀을 남깁니다. Windows에서
  작업표시줄 자동 숨김을 켰을 때와 같은 현상이라 고치지 않았습니다.
- 독이 떠 있는 동안에는 Win+Shift+S의 창 캡처 모드가 독이 쓸 수 있는 띠 전체(독 위쪽 빈 곳까지)를 창 하나로 고를 수 있습니다.
  숨어 있는 독은 골라지지 않습니다(FluentFlyout 위젯 칸은 아래 알려진 버그).
- 'PC 상태' 패널(mod.30)은 테스트 PC 한 대에서 만들고 화면 밖 그림으로만 확인했습니다.
  - Intel 보드와 DDR4의 슬롯 이름, 150% 화면, 세로 독의 패널은 실제 독에서 아직 보지 못했습니다.
  - VRAM 줄(mod.31)은 NVIDIA 그래픽 카드가 있는 PC 한 대(한국어 HWiNFO, 100% 가로 독)에서 만들고 실제 독에서 확인했습니다. 다른
    카드가 HWiNFO에 메모리 온도 센서를 주는지, 내장 그래픽만 있는 PC에서 VRAM 줄이 뜨는지(내장 그래픽의 전용 메모리가 1 GB 이상으로 보고되면 `-- / N GB`로 뜸)는 아직
    보지 못했습니다. HWiNFO의 영어 센서 이름 `GPU Memory Junction Temperature`와 NVIDIA가 아닌 GPU의 사용량 길은 실제 키로 보지 못했습니다.
  - SATA 하드 디스크(HDD)가 있는 PC에서 패널을 열면 온도를 묻느라 잠든 디스크가 깨어날 수 있습니다(HDD가 없어 확인하지 못함).
    디스크가 깨어나는 동안 패널 값이 몇 초 늦을 수 있습니다.
  - HWiNFO가 켜져 있는 동안은 값이 오래 그대로여도 씁니다. 그래서 HWiNFO는 떠 있는데 센서 읽기만 멈춘 경우에는 멈춘 값이 그대로 보입니다.
  - 설정 → 센서(mod.33)와 칸을 덜 다시 그리기는 테스트 PC 한 대에서 만들고 자동 테스트로만 확인했습니다. 숨긴 항목의 패널·칸 모습, 시간당 다시 그리기 횟수,
    예전 설정(PawnIO를 켜 둔 PC)에서 올라오는 경우, 설치 프로그램의 도우미 갱신(확인 창, 거절, `.old`)은 아직 실제로 보지 못했습니다.
  - 예전에 PawnIO를 켜 두었던 PC를 새 독으로 처음 켤 때 HWiNFO가 아직 뜨지 않았으면(로그온 직후 등), PawnIO가 설치된 PC는 '온도 읽기'가 PawnIO로 정해질 수
    있습니다(그 뒤로는 다시 보지 않음). 그때는 설정에서 HWiNFO Gadget으로 바꿉니다.
  - NVIDIA 카드는 '온도 읽기'가 끄기·PawnIO여도 VRAM 온도 줄의 자리를 잡아 두므로, 드라이버가 그 온도를 주지 않는 카드에서는 가로 독이 27 DIP만큼
    필요보다 두껍습니다.
- **알려진 버그 (mod.23 뒤 검토에서 찾음, 고치지 않음):** 모두 드물게 생기거나 영향이 작은 낮은 심각도라 고치지 않기로 하고
  여기에 적어 둡니다.
  - **설정 창 스크롤:** 노트북 터치패드의 두 손가락 스크롤(또는 한 칸보다 작게 도는 휠)로 페이지를 내리면 페이지가 픽셀 사이에
    멈춰, 토글의 1픽셀 윤곽선, 슬라이더 막대, 선택 표시 같은 선과 칸의 가장자리가 흐려 보입니다. 내리는 동안 가장자리가 반짝이고,
    멈춘 뒤에도 흐린 채 남습니다. 글자는 선명합니다.
  - **Win+Shift+S와 FluentFlyout 위젯:** 위젯이 들어간 독이 숨어 있을 때(그 모니터에 전체 화면 앱이 떠 있거나 OLED 모드가 덮을
    때, 위젯 모니터를 자동 숨김인 주 모니터로 옮겼을 때) 창 캡처 모드가 위젯 칸 크기의 빈 사각형을 창으로 고를 수 있습니다. 찍으면
    그 밑 창의 일부가 나옵니다. 캡처 도구가 실제로 그것을 고르는지는 실기기에서 확인하지 못했습니다.
  - **트레이 아이콘이 잠깐 떴다 사라짐:** 작업표시줄에 아이콘 하나를 꺼내 둔 프로그램이 실행 중에 두 번째 아이콘을 더하면(HWiNFO의
    센서 아이콘을 켤 때 등), Windows가 새 아이콘에 따로 설정을 만드는 경우 그 아이콘이 독에 1초 안쪽으로 보였다가 사라집니다.
  - **트레이 유령 아이콘:** 위 [트레이 아이콘](#트레이-아이콘-실험-기능)의 '지운 아이콘'에 적은 예외입니다. Explorer를 다시 시작하거나
    Explorer가 응답하지 않는 순간에만 생깁니다.
  - **다시 최소화한 창:** 최소화된 앱 A의 아이콘을 눌러 띄우고 0.25초 안에 다른 앱 아이콘을 누른 뒤, A의 창을 곧바로 다시 최소화하고
    A 아이콘을 누르면(A가 처음 클릭에 답한 뒤 0.5초 안) 창이 올라오지 않습니다. 한 번 더 누르면 올라옵니다.
  - **오래 누른 클릭:** 관리자 권한 창(작업 관리자, 관리자 터미널 등)이 앞에 있을 때 독 아이콘을 2초 넘게 누르고 있다가 떼면 클릭이
    되지 않습니다. 끌기 도중 관리자 권한 창이 앞으로 오면 끌던 아이콘은 놓은 자리로 가지 않고 취소됩니다(앞 창이 관리자 권한일 때
    단추 상태가 0으로 온다는 전제는 실기기로 확인하지 못함).
  - **시작 버튼:** 위 [시작 버튼](#특징)에 적은 대로, Windows나 Explorer가 켜진 지 5분 안에 작업 표시줄 시작 단추가 분명히 두 번
    빗나가면 독을 다시 켤 때까지 그 단추를 쓰지 않습니다(그동안은 셸 요청으로 엽니다). 독을 며칠 켜 둬도 다시 확인하지 않습니다.
  - **CPU 온도:** '온도 읽기'를 PawnIO로 둔 채로, 도우미가 막 뜬 순간 독이 5초 넘게 멈춰 있고(독의 질문 창이 떠 있을 때 등) 그사이 도우미가
    끝나면, 칸에 "온도: 도우미 시작 중…"이 남고 도우미를 다시 띄우지 않습니다. '온도 읽기'를 다른 것으로 바꿨다가 PawnIO로 되돌리면 풀립니다.
  - **FluentFlyout 앱 필터:** '재생 중인 미디어가 없을 때 완전히 숨기기'와 FluentFlyout의 앱 필터를 함께 쓰면, 독이 새 미디어 앱의
    이름을 지을 때마다 창이 있는 모든 프로그램을 메모리 읽기 권한으로 엽니다(읽는 것은 경로뿐이고, FluentFlyout이 건너뛰는 프로그램을
    똑같이 건너뛰려는 것). 다른 프로그램의 핸들을 지켜보는 커널 안티치트에는 이것이 보일 수 있습니다
    (FluentFlyout도 같은 프로그램을 같은 권한으로 엶. 실제 피해는 확인되지 않음).
  - **끌 때의 FluentFlyout 위젯:** FluentFlyout이 10초 넘게 응답하지 않아 독이 트레이 호스트를 멈추다 포기한 뒤, 포기한
    호스트가 아직 멈춰 있는 동안 독을 끄면, 독은 그 호스트를 다시 기다리지 않습니다. 그러면 위젯이 기본 작업표시줄로 돌아가지 못하고
    잠깐 사라지거나(FluentFlyout이 다시 만듦), 드물게 독이 끝나는 순간 오류로 끝날 수 있습니다(이론상, 재현되지 않음).

## 직접 빌드

Visual Studio 2022 Build Tools(C++ 데스크톱, Windows SDK) 설치 후:

```bat
build.bat
```

`build\LiquidDock-Setup.exe`가 만들어집니다. PowerShell에서는 `.\build.bat`, `.\build\LiquidDock-Setup.exe`처럼 앞에 `.\`를 붙입니다.
관리자 도우미가 실행 중이어도(관리자 권한 앱 창 제어를 켜 두면 독과 함께 늘 실행) 도우미와 설치 프로그램까지 빌드합니다. `build.bat dev`로 빌드하면 실행 중인 독을 조작하는 개발자용 명령(`--debug-*`, `--snap` 등)이 추가됩니다. 구조:

| 폴더 | 내용 |
|---|---|
| `src/` | 독 본체 (Win32, Direct3D 11, DirectComposition, Windows.Graphics.Capture) |
| `sensors/` | 선택적 관리자 도우미 (CPU 온도, 관리자 권한으로 실행한 앱의 창) |
| `installer/` | 설치/제거 프로그램 |
| `tests/` | 테스트 (아래) |
| `tools/llm-tasks/` | 로컬 LLM으로 돌릴 수 있게 따로 떼어 둔 작업과 자동 검사 ([설명](../tools/llm-tasks/README.md)) |

### 테스트

```bat
tests\run_regressions.bat
```

실행 중인 독이나 실제 작업 표시줄을 건드리지 않는 단위·통합 테스트(창 미리보기 포함, 47개)를 모두 빌드해서 돌립니다(각 테스트는 자기 가짜 창과 이름만 씀. 약 4분, 마지막의 독 자체 테스트 4개는 GPU(Direct3D·Direct2D)가 있어야 함). `tests\run_all.bat`은 독 빌드(`build.bat`)와 이 테스트들에 이어, 빌드된 독 코드로 숨은 창을 만들어 확인하는 상호작용·설정 테스트까지 돌립니다(6~7분, 실행 중인 독은 건드리지 않음). Windows 헤더가 필요 없는 판단 로직(FluentFlyout 모니터·재생 판단, 설정 파일 읽기, 아이콘 픽셀, CPU 온도 해석, 앱 아이콘 클릭, 작업 표시줄 앱 단추, 시작 버튼, 백그라운드 확인 주기, 대기 시간, 툴팁 캐시)은 Linux·WSL·macOS에서도 `sh tests/run_portable.sh`로 돌릴 수 있습니다. `tests/llm/`에 있는 테스트(로컬 LLM 작업 팩에서 `--apply`로 넣은 것)도 두 스크립트가 함께 돌립니다.
주의(알려진 버그, 고치지 않음): `run_regressions.bat`은 충돌(접근 위반, abort)로 끝난 테스트도 통과로 셉니다. 끝 줄 `all regression tests passed`만 보지 말고 테스트마다 자기 결과 줄(`ALL PASSED (N checks, 0 failures)`, `RESULT ...` 등)이 있는지 확인하세요. 결과 줄 없이 다음 테스트로 넘어간 것이 있으면 그 테스트가 충돌한 것입니다.
`tests\run_start_menu_live.bat`은 독의 시작 버튼 코드로 실제 시작 메뉴를 몇 번 열고 닫으며 확인합니다. 먼저 작업 표시줄의 시작
단추로, 이어서 그 단추 없이 셸 요청으로 확인합니다(약 30초, 그동안 마우스와 키보드에서 손을 떼 주세요. 관리자 권한이 아닌 일반
실행이 독과 같은 조건입니다).
`tests\run_taskbar_probe.bat`은 작업 표시줄(독이 숨긴 것 포함)이 UI 자동화로 어떻게 보이는지, 곧 시작 단추와 앱 단추가 어디 있고
어떤 방법으로 누를 수 있는지를 읽기만 해서 보여 줍니다(아무것도 누르거나 바꾸지 않음). 독을 켠 채로 한 번, 끈 채로 한 번 돌리면
작업 표시줄이 숨을 때 무엇이 달라지는지 알 수 있습니다.
`tests\run_preview_live.bat`은 독의 창 미리보기 코드로 실제 창과 실제 미리보기를 만들어 화면의 색을 읽어 확인합니다. 모니터와
독 위치마다 테스트용 창 12개(그대로 있는 창, 캡처를 막은 창, 최소화된 채로 시작한 창, 화면에 나왔다가 최소화된 창)를 만들고,
최소화된 창이 최소화 직전 색으로 나오는지, 화면에 나온 적이 없는 창은 Windows가 주는 아이콘 카드로 나오는지, 카드의 닫기 단추와 휠 클릭이
테스트 창을 실제로 닫는지 확인하고 Windows가 알려 준 크기를 남깁니다(모니터·위치마다 약 4초, 그동안 이 창을 앞에 두고 마우스에서 손을 떼 주세요. 미리보기 그림은
`build\tests\preview-live\`에 남음). `build.bat` 없이 돌아갑니다.
`tests\run_taskbar_apps_live.bat`은 독의 작업 표시줄 앱 단추 코드로 실제 작업 표시줄을 확인합니다. 먼저 읽기만 해서 앱 단추마다
id와 이름, 실행 중인 창마다 독이 찾을 단추를 보여 주고, 이어서 테스트용 창 하나를 만들어 그 단추가 주는 누르는 방법을 보여 준 뒤
그 단추를 세 번 눌러 창이 앞으로 오고, 내려가고, 다시 오는지와, 독이 기다리기를 그만둔 누르기는 그 뒤에도 눌리지 않는지
확인합니다. 단계마다 테스트가 자기 창의 시작 상태(뒤에 있음, 앞에 있음, 최소화됨)를 먼저 만들어서 한 단계의 실패가 다음 단계로
번지지 않고, 누르기 전에 앞 창 권한을 탐색기에 넘겼는지도 출력합니다. 단추를 누를 방법이 없는 Windows(확인한 25H2·26H2 빌드)에서는
누르지 않고 창이 그대로인지 확인한 뒤 남은 누르기 단계는 건너뛰고, 독이 기다리기를 그만둔 누르기가 눌리지 않는지는 그대로
확인합니다. 누르기가 늦게 도착할 수 있으면(탐색기가 답하지 않음) 그 뒤 단계는 돌리지 않습니다(다른 프로그램의 창은 누르거나 옮기지
않음. 약 10초, 그동안 이 창을 앞에 두고 마우스와 키보드에서 손을 떼 주세요). 독을 켠 채로, 곧 작업 표시줄이 숨은 채로 돌립니다.
`tests\run_taskbar_apps_diag.bat`은 작업 표시줄 앱 단추를 눌렀을 때 실제로 무슨 일이 생기는지 잽니다. 테스트용 창 하나의 단추만,
그 창을 뒤에 둔 채·앞에 둔 채·최소화한 채로 한 번씩 누르고, 탐색기에 앞 창 권한을 넘겼는지, 단추마다 주는 누르는 방법, 깜빡임,
앞 창 변화, 그 창이 받은 메시지를 기록한 뒤 `VERDICT` 한 줄로 정리합니다. 기본은 독이 이제 쓰지 않는 접근성 기본 동작으로 누르고
(확인한 25H2 빌드에서는 아무 일도 하지 않음), 명령 창에서 `tests\run_taskbar_apps_diag.bat dock`으로 돌리면 독의 방식으로 누릅니다.
누른 뒤에는 3초씩 지켜보고, 늦게 도착할 수 있는 누르기 뒤에는 남은 단계를 돌리지 않습니다. 독을 켠 채로 한 번, 끈 채로 한 번
돌리면 작업 표시줄이 숨은 탓인지 알 수 있습니다(다른 프로그램의 창은 누르거나 옮기지 않음. 독처럼 아무 프로그램도 쓰지 않는
키(0xE8)로 앞 창 권한을 받음. 약 15초, 그동안 이 창을 앞에 두고 마우스와 키보드에서 손을 떼 주세요).
아래 실기기 테스트들도 실제 Windows에서만 알 수 있는 것을 봅니다. 다른 프로그램의 창은 닫거나 누르지 않습니다.
- 읽기만 하는 것(돌리는 동안 마우스를 써도 됨):
  - `tests\run_tray_uid_live.bat` – 실행마다 아이콘 번호가 바뀌는 프로그램(MSI Afterburner 등)의 트레이 설정을 Windows가 어떻게
    두는지, 테스트 자신의 아이콘으로 봅니다(약 30초. 자기 아이콘만 띄우고, Windows가 테스트 프로그램의 트레이 설정 항목을 하나 남김).
  - `tests\run_taskbar_apps_live_lookup.bat` – 작업 표시줄마다 앱 단추와 누르는 방법, 모니터마다 독이 누를 단추(1~2초, 독을 켠 채로).
  - `tests\run_apps_model_live.bat --logged pins` – Windows의 고정 목록을 셸이 읽는 대로 읽어, 독의 첫 실행 가져오기 순서와 비교합니다.
  - `tests\run_admin_live.bat` – 설치된 관리자 도우미가 새 판인지, 다른 프로그램을 거절하는지, 여기서 아무것도 써 넣을 수 없는지,
    모든 프로세서가 바쁠 때도 1.5초 안에 답하는지 등(약 5초, '관리자 권한 앱 창 제어'를 켠 채로).
- 테스트 자신의 창을 쓰는 것(손을 떼 주세요): `tests\run_apps_model_live.bat`의 restore 검사(약 5초, 바쁜 앱의 최대화 창이 최대화로
  돌아오는지), `tests\run_preview_live_dpi.bat`(배율이 다른 모니터 사이에서 미리보기 창의 자리와 크기, 약 2초, 노트북에 외부
  모니터를 연결했을 때).
- 사람이 직접 하는 동안 보는 것: `tests\run_tray_live.bat`(트레이 아이콘 클릭 좌표, 최대 약 3.5분), `tests\run_dock_render_live.bat`
  (터치패드·휠이 보내는 값, 15초), `tests\run_dock_layout_live.bat`(전체 화면·잠금 화면·마우스 단추를 독이 어떻게 보는지, 60초,
  `build.bat` 뒤에), `tests\run_fluent_live.bat`(FluentFlyout 위젯과 Flyout, 25초(빌드 제외), FluentFlyout과 독을 켠 채로),
  `tests\run_system_live.bat`(HWiNFO 설정을 바꾸는 동안 Gadget 키, 90초), `tests\run_start_menu_visibility_live.bat`(시작 메뉴를
  열고 닫고 Explorer를 다시 시작하는 동안, 약 2분, 안내가 콘솔에 나오므로 더블클릭으로).

`tests\run_desktop_checks.bat`은 위 실기기 테스트 가운데 여러 개를 한 번에 돌립니다. 새 독을 설치하고
관리자 도우미를 바꾼 뒤(위 '관리자 권한으로 실행한 앱'), 독을 켠 채로 실행합니다.
- 1부(약 1분, 읽기만, 마우스와 키보드를 써도 됨): `run_taskbar_apps_live_lookup`, `run_apps_model_live pins`, `run_tray_uid_live`,
  `run_fluent_live 0`, `run_admin_live`.
- 2부(약 2분, 손을 떼고 이 창을 앞에): `run_taskbar_apps_live`, `run_start_menu_live`, `run_preview_live`, `run_apps_model_live restore`.
  닫는 것은 테스트 자신의 창뿐입니다. `tests\run_desktop_checks.bat part1`은 1부만 돌립니다.
- 결과는 `build\desktop-checks\<컴퓨터 이름>\`에 테스트마다 하나씩 남고, 끝에 `dock.log`, `settings.ini`, `sensors.log`도 그 폴더에
  복사됩니다. 그 폴더를 압축해 전달하면 됩니다. 테스트를 그 자리에서 빌드하므로 `build.bat`처럼 Visual Studio 2022 Build Tools가 필요합니다.

`run_regressions.bat`, `run_all.bat`, `run_taskbar_probe.bat`, `run_taskbar_apps_diag.bat`과 이름에 `live`가 든 스크립트는 출력을
`build\tests\<이름>.log`에도 남기고, 더블클릭으로 실행했으면 끝난 뒤 창을 닫지 않고 기다립니다.
